最终审查指出：
- GAP-01：系统把“提供了 MAP”误报为“具备 Object / Module Attribution”，但实际对象贡献信息未进入快照与 UI；误报还传播到 CLI 和 Release Bundle。

三、唯一授权修正 A0-01：Object Attribution 能力声明纠正
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

核心问题：
目前 crates/firmwaresight-artifact/src/pipeline.rs 的 build_capabilities() 对 MAP 存在性与对象归因可用性使用了相同条件；crates/firmwaresight-core/src/domain/capability.rs 的 with_map(provision, attribution) 会把 attribution 状态写入 Capabilities。当前对象贡献没有在 BuildSnapshot / Storage / UI 中形成可查询的实际结果，Compare 则明确报告 unavailable。

必须独立确认：
- map_evidence 的确仅说明 MAP 已解析，而不代表可提供对象级归因结果；
- 当前 production 不持久化、不展示对象/模块归因记录；
- 纠正状态时，MAP Provided/Available 的事实与 section/region/load-address 分析仍然保持正确；
- 哪些消费者依赖 object_attribution 的 availability。

实施要求：
1. 在源头将对象归因状态改为与实际可交付能力一致；在当前实现确实无可查询对象归因结果时，不得继续报 Available。应选用现有 canonical Availability 枚举与真实事实相符的状态，避免发明第五种证据分类。
2. MAP 的存在、MAP region evidence、已有 Section/Symbol 结果不能因此变为 Unavailable。
3. 对用户可见的 Analyze、Overview、CLI report、Release Bundle 等输出检查实际显示是否一致。不要只在一个 React 页面隐藏错误文本，而让报告继续误报。
4. 为 MAP 提供 / 未提供各建立回归覆盖；MAP Provided 与 Object Attribution Unavailable 应可同时成立；与现有 Compare 的不支持理由一致。
5. 如需要变更既有 report/golden 中的一行陈述，先检查其契约地位，再做严格对应的预期更新与差异证明。不得利用脚本批量重新生成无关 Golden。

**本轮禁止：**
- 新增 ObjectContribution 表、字段、持久化模型、对象级 diff 或对象归因 UI。
- 修改 map.rs 的绝对路径筛选机制、对象身份归一化及 archive-member 语义；它们属于后续独立设计。
- 把所有 MAP 行简单相加并声称获得精确对象级 FLASH 大小。
- 更改 MemoryFootprint、Budget 或 Gate 规则判断。
- 以“能力变更”为由扩大兼容范围。

如果把虚假声明纠正为真实状态会意外改变 Gate Verdict、Snapshot ID、Release ID 或已承诺的证据语义，立即暂停并上报最小可复现证据，不得自行继续。

十、Git 交付授权与最终停止
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

本提示词授权针对 A0 的最小代码/测试/必要治理文档改动。在预检干净、全部本地门禁通过、变更路径完全属于 A0 后，允许正常 fast-forward commit/push 到既有授权分支，并按仓库规定回读其 CI 结果；禁止 force push、amend 已发表历史、删除分支或合并其它工作。

如出现未预期的工作树改动、权限疑问、阻断性回归、安全/Schema/公共契约变更，STOP，不得为了获得绿灯而自行扩大授权。远端 CI 若失败，仅允许对本次 A0 造成的范围内问题作有证据的纠正；超出范围须返回请求授权。

交付时报告：
- Git HEAD / origin/main 是否一致（如已推送）；
- 工作树是否清洁；
- 变动 commit id 和文件清单；
- 本地 17-step gate；
- CI run ID、head SHA、job-by-job status；
- 四个 A0 子项结论：FIXED / NO_CHANGE_WITH_EVIDENCE / BLOCKED；
- 保留的 Owner 决策 D07-1 至 D07-6；
- U1、V1、研究构建、参与者及指标状态没有被本轮重写；
- 明确说明 A0 不是产品价值验证，也不是新 V1 cohort。

本轮完成状态仅为：
A0_PRODUCT_TRUTHFULNESS_CORRECTIVE = COMPLETE / or PARTIAL_WITH_EXPLICIT_BLOCKERS

然后停止。不得自动进入 Stage A（Evidence Loop）、Stage B（Object Attribution）、V1、B1、RC 或 GA。

我们最终期待的不是“又一个绿 CI”，而是 FirmwareSight 从界面、CLI 到 Release Bundle，不再对当前实际上做不到的事情作出错误承诺。

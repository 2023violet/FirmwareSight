【严格范围】
1. 明确隔离三种状态：Application Preferences（本机 UI）、Project Policy（firmwaresight.toml，保持现有）、Session State（临时当前页/筛选等）。偏好不得进入 CLI 机读输出、Gate policy fingerprint/run id、release id、portable manifest/JSON、SnapshotId、Bundle。
2. 基于真实现有代码决定最小的 schema_version=1 偏好存储路径；优先操作系统标准 application-config directory；本地不上传、不联网、不记录固件原始字节。偏好读写必须校验类型/枚举、未知或未来版本处理、安全默认值、损坏文件可恢复且不静默销毁原字节、受控原子写入/失败可见、两次保存竞争有确定语义。Windows 文件替换语义要实际测试；不要仅用 UNIX rename 假设宣称跨平台原子性。
3. B1-U1 首版必须至少真正支持：
   A) display.size_unit: bytes（默认）/KiB；直接复用已有 SizeUnitSwitch、format.ts 与 App 的 unit 状态。设置与任何页面的单位切换双向同步；重启保持；不重算分析数据。
   B) General 中只读 Local-first/无云账号能力事实、About/诊断入口（复用现有页面）；如功能源事实未证则不宣称“零网络/零遥测”。
   C) Reset application preferences: 清楚的确认及恢复，不能影响现有 SQLite build/gate/release 历史、文件、项目策略。保存失败不得假装成功。
   D) 任选一个当前可独立验证且不侵入 Core 的第二项真实偏好，例如启动页 Analyze/Last page（仅当可安全保留页面状态，且不复活旧 Gate 判定）。若复杂度/隐私超过限定范围，可放弃第二项并在报告说明，不得为了凑数加占位开关。
4. 在现有导航低调增加真实 Settings 页；至少有 General、Appearance（单位选择）和 About/Diagnostics 访问。仅显示本轮真实生效的控件。主题 System/Light/Dark 与语言 System/zh-CN/en 属于后续 B1-U2 / B1-U3：此轮不实现，不显示不可用开关。注意已有设计文档“Settings 仅项目级”与 v0.2 的“用户偏好独立于项目 Policy”存在设计边界变化；须先按治理规则明确采纳新版应用偏好信息架构，使用最小范围正式设计决策（如必要，Owner 确认），绝不直接改写已 Accepted ADR。
5. 所有设置经受键盘 Tab/Space/Enter、焦点可见、缩放、长英文/中文路径、屏幕最小窗口 1024x720 验收。遵守现有 semantic tokens、左侧导航、配色、组件；不引入深色设计、不引入新视觉体系。
6. 设计为后续主题/语言自然接入的单一偏好读取与更新机制，但不得提前批量加入未用字段和 i18n/theme 第三方依赖；新增依赖必须按 AGENTS.md §4 审查并说明为何现有库不足。

【测试驱动的验收】
T01 首次启动、配置缺失 → bytes 与安全默认值生效，Settings 控件一致。
T02 在 Analyze 或 Compare 选择 KiB → Settings 同步，跨页面、重启仍 KiB；反向设置 bytes 同步。
T03 在 Settings 修改单位不更改 Rust Core 事实、SnapshotId/Gate run id、policy sha、release id、CLI JSON、goldens；有自动化回归证明。
T04 非法枚举、损坏 JSON、未知 schema_version → 不崩溃、不覆盖原数据、显示可恢复解释并安全回退。
T05 配置目录不可写、保存中断/失败 → 不显示“已保存”，不会损坏旧有效配置；按实际平台实现测试。
T06 Reset 只清偏好、不删 SQLite Gate/Build/Release、用户工程文件及导出；重启后保持默认。
T07 快速连续修改偏好、重启/多页面交错修改不丢最近一次成功保存的数据。
T08 无通用 WebView 文件读取 API、新网络/账号插件/遥测，路径不流入 Portable Bundle。
T09 键盘操作、焦点、1024x720 截图/实机观察、Long-label 测试通过，导航无死入口。
T10 cargo fmt/clippy/test + UI typecheck/lint/test/build + IPC binding drift + contract/schema golden/drift，保留 CI 以前的所有关键测试；说明本机/CI/实机证据界限。

PRE-0.5 Memory Accounting Fixture Hardening — Mandatory
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

P0 的 memory accounting 不允许只靠普通 host ELF + section-name heuristic 宣布通过。

必须区分两个真实 fixture 角色：

## Fixture A — Parser Infrastructure Fixture

用途：

- format detection
- object parser
- architecture
- bitness
- endianness
- entry
- sections
- symbols
- SHA-256
- malformed/no-panic
- deterministic snapshot

可以是当前 host 编译得到的真实 ELF。

## Fixture B — Memory Accounting Proof Fixture

用途：

证明：

```text
nonvolatile/load image footprint
!=
runtime RAM footprint
```

并真实证明：

```text
.data
可以同时贡献：
- load/nonvolatile bytes
- runtime RAM bytes
```

Fixture B 必须具有显式、可重复的 load/runtime evidence。

优先采用：

```text
main.c
+
controlled linker script
+
GNU ld / compatible real linker
```

至少构造：

```text
ROM region
RAM region

.text     -> ROM
.rodata   -> ROM
.data VMA -> RAM
.data LMA -> ROM
.bss      -> RAM
custom alloc section -> explicit region/evidence
```

可以使用 host ELF + 自定义 linker script，
只要 ELF program/load evidence 与 linker layout 能够确定性验证。

如果环境存在：

`arm-none-eabi-gcc`

可以额外增加 embedded ARM fixture，
但 P0 不得依赖本机必须安装 ARM GCC 才能完成 parser infrastructure。

### Memory PASS 禁止条件

如果 `.data` 双重计算只是因为：

```text
section.name == ".data"
```

则：

# Memory Accounting NOT PROVEN

即使数值“碰巧正确”，也不能判 P0 memory PASS。

Section-name heuristic 只能：

```text
Derived / low-confidence
```

不得作为：

```text
Observed
```

不得作为 Hard Gate foundation。

Golden 必须同时验证：

- numeric totals
- source locator
- evidence classification
- accounting rule/source

## FAIL

得到真实技术否定证据，例如：

- memory accounting 语义错误；
- parser 对 malformed input panic；
- deterministic JSON 不稳定；
- Core/CLI/Desktop facts mismatch；
- typed IPC contract 漂移；
- storage transaction 产生 half-complete visible state。

## BLOCKED

当前环境/authority/工具链使 mandatory 验证无法完成，
但尚不能得出技术错误结论。

例如：

- 冻结 Rust toolchain 无法获取；
- repository authority 真冲突；
- 必须新增第 5 个 library crate 才能继续；
- local/remote Git divergence 无法安全自动处理。

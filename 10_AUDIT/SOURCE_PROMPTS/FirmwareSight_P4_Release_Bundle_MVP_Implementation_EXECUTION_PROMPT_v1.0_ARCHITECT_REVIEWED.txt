"git commit succeeded, therefore the commit is still local."

git fetch origin

inspect the exact remote delta immediately.

record it as a real external fact.

Do NOT:

- duplicate-push blindly
- force push
- rewrite history to recreate a desired local/remote sequence
- claim a commit was unpushed without checking origin/main

This is a workflow fact, not a product feature.

It represents a Gate-qualified release candidate.

Therefore bundle generation requires:

disposition effective severity =
PASS

Reject bundle preparation when disposition is:

BLOCK
REVIEW

that is a different feature and not P4.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

A stored GateRun may become stale after:

- Git HEAD changes
- Git dirty state changes
- config changes
- Release Notes changes
- snapshot/baseline selection changes

Therefore:

Prepare Bundle MUST NOT blindly trust an old run.

Before creating a BundlePlan:

re-observe the current project context using the same P3 adapter
and recompute Gate with the same current snapshot + optional baseline.

The newly computed deterministic run id must equal the selected stored GateRun id.

If different:

reject with typed error:

GATE_CONTEXT_CHANGED

Remediation:

Run Gate again and review the new result.

This prevents:

old PASS
+
new dirty Git/config/notes
=
false release bundle.

Do not duplicate Gate semantics in P4.

Reuse P3.

20. MANIFEST / SHA256SUMS SELF-REFERENCE RULE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

A file cannot meaningfully contain its own cryptographic hash without a fixed-point scheme.

Do NOT fake self-hashes.

Use one explicit integrity model:

A. `SHA256SUMS`

Contains hashes for all payload files EXCEPT:

- SHA256SUMS itself
- release-manifest.json

B. `release-manifest.json`

Its `files` array contains:

ALL bundle files except:

- release-manifest.json itself

Therefore manifest.files DOES include:

- SHA256SUMS
- artifacts/*
- analysis.json
- diff.json if present
- gate-results.json
- accepted-reviews.json
- release-notes.md if present
- release-report.html

This removes the cycle.

Document this exact rule in:

release-manifest `extensions.integrity_model`

and in release-report.html.

US-004 "manifest has file hashes" is satisfied for every other bundle file;
manifest self-hash is mathematically excluded and explicitly documented.

Never insert:
sha256 = ""
or zeros
for self.

<64 lowercase hex><two spaces><relative/path>

LF endings.

Paths:
forward slash `/`

case-insensitive lexicographic by normalized bundle-relative path,
with deterministic tie-break.

No:

backslash
`..`
leading slash

Bundle SHA256SUMS is a different artifact.

22. FIRMWARE ARTIFACT COPY SAFETY
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Raw artifact source files are not stored inside SQLite.

Therefore Bundle export may need to re-read the current snapshot's source artifact paths internally.

Before copying EACH current release artifact:

1. stat
2. regular-file check
3. streaming SHA-256
4. compare against immutable snapshot artifact hash
5. compare byte size
6. only then stage the copy

If:
missing
changed
unreadable
not regular

FAIL CLOSED.

Do not export bytes under a hash that belongs to old content.

Typed error example:

ERR-BUNDLE-6103
SOURCE_ARTIFACT_CHANGED

Remediation:

Re-analyze the intended artifact or restore the exact bytes.

Do not automatically update snapshot hash.

Snapshot stays immutable.

2. write all payload files
3. fsync/flush where appropriate/practical

- rename staging → destination
- only after success remove backup

refuse replacement.

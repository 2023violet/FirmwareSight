Measured F2 defect:

<Details ... />

Details.tsx

Current CSS puts:

on the `<table>` itself.

The table carries many columns and most cells are:

The issue must be solved as a table/layout problem,
not by deleting columns.

Acceptance sizes:

A.
1024 × 720
the frozen desktop minimum

B.
1056 × 799
the F2 defect/default measured size

C.
1440 × 900
the frozen design target

At A and B:

PASS requires:

- Section Name remains legible;
- headers remain legible;
- cells do not collapse to near-zero width;
- Unknown reason text remains readable/viewable;
- table content remains reachable;
- the page itself does not acquire uncontrolled horizontal overflow;
- if horizontal scrolling is needed, the TABLE AREA owns it;
- no column is silently hidden;
- no data is removed;
- sort/filter/pagination remain functional;
- keyboard focus remains usable.

Do NOT solve by:

- reducing font below design tokens;
- hiding columns at minimum width;
- replacing values with ellipsis without a full-view path;
- making the whole app window horizontally scroll;
- hard-coding one host's 1056 px screenshot geometry.

Preferred design direction:

a semantic table viewport/wrapper that owns horizontal overflow,
with table intrinsic minimum sizing rather than destructive column collapse.

This is a direction, not an implementation mandate.

Measure before choosing.

6. U2 BUNDLE CONTRACT — THE SIX PROOF LINKS
════════════════════════════════════════════════════════════════════

Implement ONLY the one project/Bundle path frozen in §3 and §6.

L-1 VERDICT SUBJECT:
  Gate evaluation must run on the exact GateContext bearing the same
  attachment set that gets planned. A library-level positive scenario
  proves a run with required BIN/HEX can PASS; no-attachment remains BLOCK
  when policy requires them. No empty hardcoded vector in the path.

L-2 IDENTITY:
  Gate run id is computed from `/2` canonical text when attachments
  exist. Mutate only one attached byte: run id changes; snapshot id does
  not. Rename byte-identical file: Gate run id remains stable.

L-3 STORED RUN RECOMPUTE:
  Bundle preparation with selected stored Gate run MUST recompute its
  context using its selected attachment facts. Missing, added, changed,
  re-declared attachments must not match stale Gate run silently. Under
  original stored run, re-judging without source files uses stored facts;
  building a NEW bundle when files are absent is correctly refused.

L-4 MEMBERSHIP AND BYTE VERIFICATION:
  Introduce one `verify_attachments` sibling to `verify_sources`:
  stat, regular-file check, nonempty, streamed SHA-256, digest equality,
  size equality, membership in `GateContext.attachments` by kind+digest
  and any other necessary frozen fact. Attachment not in judged set =>
  refusal BEFORE destination write. Do not accept a file only because
  its leaf/path or extension matches. Context selection is not permission
  to ship an arbitrary byte sequence.

L-5 PREVIEW/EXPORT STALENESS:
  Attachments contribute to InputChecks.sources in the same canonical,
  deterministic source row set used during preview and export.
  Source modified (same pathname, new digest or size) => refuse.
  New or removed attachment between preview and export => E-4 typed
  `AttachmentSetChanged{name,change}`, not a misleading pairwise file
  change. A rename with unchanged bytes invalidates the plan but leaves
  the Gate run id unchanged, and changes release identity.
  `changed_leaf()` must be set/membership-aware; no zip-by-index bug.
  Preview and publish MUST call the same attachment validation function
  and same core observation path, not two subtly different validators.

L-6 SELF-VERIFYING OUTPUT:
  Bundle includes the exactly selected files with collision-safe
  `artifacts/<name>` path, full manifest files[] hash/size and
  SHA256SUMS entries. `verify_bundle()` recomputes release identity using
  the actual shipped list and refuses after tampering with an attachment.
  Old P4 release inputs, goldens and verification behavior unchanged.

Six separate proof rows in the report, each with real named tests and a
negative control. A single broad happy-path bundle test is NOT enough.

4. ROOT CAUSE — ARCHITECT VERIFIED
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

At 6f35b14 / current main:

Analyze.tsx keeps:

const summary = lastGood;

and intentionally retains the last-good summary after a later analysis fails.

This is valid for the retained historical report.

The lower report already receives:

stale={error !== null || pendingSelection}

and renders explicit previous/last-good wording.

However, the top capability strip currently renders from:

summary.capabilities.elf
summary.capabilities.map
summary.capabilities.git

whenever summary != null,
without conditioning those capability chips on stale/current-attempt state.

Therefore a failed new analysis can show:

current error / current selected artifact

AND simultaneously:

green capability chips belonging to the previous successful snapshot.

That is the defect.

Do NOT "fix" it by deleting last-good retention.

Last-good retention is useful and already part of product behavior.

The correction must separate:

CURRENT ATTEMPT STATE

from:

LAST GOOD RETAINED EVIDENCE

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
5. REQUIRED UX CONTRACT
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The top capability/status strip must describe the CURRENT attempt/context.

It must never silently borrow capability facts from lastGood when:

error != null

or:

pendingSelection == true

or any equivalent state where the selected/current artifact has not produced a successful current summary.

Required behavior:

A. Current successful analysis

Show the normal capability chips derived from the successful CURRENT summary.

Example:

ELF supported
MAP provided
Git available

B. No analysis yet

Show neutral no-analysis / input-ready presentation,
not invented capabilities.

C. Selection changed but not yet successfully analyzed

Do NOT show the last-good capability chips as if current.

Use a neutral current-context presentation such as:

"Current selection not analyzed"

and, if useful:

"Previous result retained below"

D. Current analysis failed

Do NOT show last-good capability chips as current.

Use a neutral/error-context presentation such as:

"Current analysis failed"

and optionally:

"Previous result retained below"

The exact human wording should follow the existing U1 visual language.

Do not add a new domain state.

Do not map failure to PASS/REVIEW/BLOCK/UNKNOWN/N/A unless that mapping is already semantically correct.

This is presentation state,
not a Gate verdict.

E. Retained lower report

The last-good report and Details may remain visible if current product behavior intentionally preserves them.

But they MUST remain explicitly labelled:

Previous analysis / Last good analysis

and must not be confused with current-attempt facts.

The exact React implementation may differ,
but the semantic contract above is required.

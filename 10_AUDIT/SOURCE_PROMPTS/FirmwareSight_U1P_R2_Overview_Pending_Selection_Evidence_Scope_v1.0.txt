3. VERIFIED ROOT CAUSE AND BEHAVIOUR

App.tsx owns four separate facts:
selection: SelectionDto|null
lastGood: AnalysisSummaryDto|null
analyzedSelectionId: string|null
gateRun: GateRunDto|null

U1P-R1 already passes analyzedSelectionId to Overview.
The existing readinessScope guard identifies selectionPending when
selection.selectionId !== analyzedSelectionId; it correctly withholds a current Gate verdict.

However Overview.tsx also renders:
<InputRow summary={summary} selection={selection} ... />
<Readiness ... />
<Facts summary={summary} ... />

InputRow destructures capabilities from summary (retained lastGood) but obtains mapAttached and
mapFileName from selection (new pending input). Its capability chip and explanatory detail can
therefore refer to DIFFERENT ARTIFACTS in the same cell.

The user-visible Flash/RAM/Symbols/Evidence figures derive from lastGood, yet lack a prior/retained
label when a new selection has not completed Analyze.

This is NOT a Core or Gate evaluation error. It is a presentation-scope boundary error.
Do not fix it by clearing lastGood or deleting history.

4. REQUIRED NEW STATE CONTRACT

A. CURRENT ANALYZED SELECTION
When summary belongs to current selection, show all current capabilities and all current metrics.
Do not change U1P decision-first hierarchy. The matching Gate run still shows its real verdict
and full judged snapshot ID.

B. DIFFERENT CURRENT SELECTION, NOT YET ANALYZED
When selection != null and selection.selectionId != analyzedSelectionId, show the SELECTED artifact
as pending. Do not display retained ELF/MAP/Git capability chips as CURRENT.
Do not show retained Flash/RAM/Symbols/Evidence values as the selected artifact's current facts.
Preferred minimal design:
- a compact, neutral current-selection band naming the new file and stating NOT ANALYZED;
- action to Analyze the selected artifact;
- optional retained historical analysis panel only with explicit “Previous analysis” heading
  and its real snapshot identity, never mixed into a current status band;
- Gate readiness stays “Not assessed for the selected artifact”.

C. MAP INTEGRITY

must not appear as a statement about one current selected input.

D. PARSE FAILURE AFTER PREVIOUS SUCCESS

no prior green capability presented as current. Overview must not turn a failed new selection
into a newly successful analysis.

E. RETURN TO SUCCESS
After a genuine new successful analysis, replace current capability and metric values
with those from the newly authoritative summary. No artificial sticky pending state.

F. DIFFERENT BUILD WITH BOTH SUCCESSFULLY ANALYZED

summary, its capabilities/metrics may remain visible, even if an older Gate run concerns another build.

G. DIFFERENT POLICY

was chosen or judged. No automatic Gate rerun.

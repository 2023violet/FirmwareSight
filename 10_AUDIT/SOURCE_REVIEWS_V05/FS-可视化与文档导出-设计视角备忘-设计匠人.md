## 0. 判断基准与一句话立场

设计哲学对"可视化"的定义很窄：**图形是仪器的刻度与指针，不是装饰画**。一个图形要存在，必须让某个具体判断更快或更准；答不出"它帮用户回答什么问题"的图形，一律按营销面处理。

评审每个候选形态，用三条准则：

| # | 准则 | 来源 |
|---|---|---|
| 准 1 | **判断准则**：该形态帮用户回答哪个具体问题？答不出就不进产品 | P4 一屏一个主焦点 / "为装饰添加图表"禁令 |
| 准 2 | **上下文准则**：离开颜色与图形还能读吗？每个数字带上下文（相对谁/占比/最大贡献者/是否超预算，至少占一） | P2 数字必须带上下文 / tokens changelog #9 |
| 准 3 | **职权准则**：图形只呈现事实，不做判决——好坏判断只属于 Gate 规则，图形不得预支情绪 | 语调三律"说事实不做判决" |

**一句话立场：图表是表格的放大镜，不是表格的替身。** 所有图形从表格数据派生、可点回数据行（"图即索引"）；表格永远在场，图形只是让表格里"该被看见的那一行"更快被看见。

## ① 分析完成后的可视化形态 · 逐项评审

### A1 · Section / FLASH / RAM 占用 ranked bars（含预算线）

- **帮助判断**："Flash 装不装得下？RAM 被谁吃了？"——嵌入式工程师的母语就是水平条形 + 数值，这是全产品性价比最高的一张图。
- **价值判断：高**。已是 P0 验收口径的一部分（分析必须给 section 级占用与最大贡献者）。
- **是否符合哲学：完全符合**。P2 的"是否超预算"上下文由**预算线**承载：1px `border.default` 竖线 + mono 文字标注（如 `budget 512 KB`），**不用红染整根 bar**——超没超由 Gate 规则说话，图只画事实（准 3）。
- **相容性：✅** 优先级链第 2 位；且形态上是"表格内嵌数据列"（UI-02 已落地），表格仍是主呈现。
- **边界**：bar 按名次取 `chart.seq.1–5` 蓝阶（深＝大），每根伴随 mono 数值标注；溢出部分归 `chart.rest`。浅档 `chart.seq.1/2` 不单独承载信息。

### A2 · Symbol 级 Top-N 下钻表

- **帮助判断**："这 12 KB 到底是哪个函数涨的？"——下钻终点必须是 symbol 与 Evidence。
- **价值判断：高，但只在"Top-N 表"形态下高**。20–50 行的 ranked 表是对的；几千个 symbol 的连续条形图是错的（没人读 3000 根 bar，渲染也是负担）。
- **是否符合哲学：符合**。下钻用**行展开 + 面板**，不弹新页面（动效条款只允许行展开类 motion）；Analyzers → section → symbol → Evidence 的路径一键可达（P1）。
- **相容性：✅** 纯 table + ranked bars 组合，不引入新图型。
- **边界**：默认 Top 20 + "show more" 展开为 Top 50；表尾给聚合行 "其余 N symbols（chart.rest 语义）"。

### A3 · Treemap（size 构成 + 下钻）

- **帮助判断**：唯一能直观呈现"嵌套空间构成"的形态——section 内部哪些 .o/.a 占了大块、碎片化程度如何，一眼可见。真实用途是**找最大可优化对象**。
- **价值判断：条件性高**。它是四级优先链里最"像玩具"的形态：做得好是仪器（单色蓝阶、hover 数值、点击联动表格），做得差就是营销图（彩虹色块）。
- **是否符合哲学：有条件符合**——基线明确允许 treemap **仅用于 size 构成**；商业模式文档也写明不为 treemap 付费，所以它**永远不作为产品门面**。
- **相容性：✅（三重约束下）**：① 仅 size 构成场景；② 只用 `chart.seq` 蓝阶 + `chart.rest`，禁彩虹分类色；③ **必须与表格双向联动**（点块高亮表格行、点行高亮块），否则降级为纯装饰、不进产品。
- **边界**：叶子矩形 > ~300 时聚合为"其他"（`chart.rest`）；下钻用面包屑（FLASH → .text → libm.a → …），每层仍可点回表格。

### A4 · Compact stacked bar（FLASH / RAM 构成并排）

- **帮助判断**："这个 build 的 Flash 都花在哪、RAM 都花在哪"——单屏内双构成对比，比两张独立图省空间。
- **价值判断：中高**。是 A1 的紧凑变体，适合 Overview 摘要行与导出报告；探索明细时仍回到表格。
- **是否符合哲学：符合**（dense not crowded）。约束：分段 ≤ 5（`chart.seq.1–5`，其余归并 `chart.rest`）；段间 1px `bg.surface` 隔断；每段 mono 数值标注；禁渐变。
- **相容性：✅** 优先级第 3 位，仅在 ranked bars 表达不了"总量—构成"关系时启用，不做默认图型。

### A5 · Compare delta 可视化

- **帮助判断**："这次比上次变了多少、谁贡献的？会不会把我撑爆？"——产品差异化核心，P0 验收已写死"禁止只给 +8KB"。
- **设计主张：delta 的第一呈现永远是 Diff Row 表格**（old / new / Δ 同列，added/removed 显示 `—` 禁 0 冒充——已冻结）；图形只做一件事：**"Biggest growth contributors" ranked bars 面板**（UI-03 已落地），点击下钻 symbol。
- **一个必须守住的语义**：**尺寸增长 ≠ 变坏**。Δ 的正负只表达事实方向，**禁止用红绿表达好坏**（红绿已被 added/removed 行底色占用，且"涨了 = 危险"是替用户判决，违反语调三律）。Δ 数值一律 mono + 显式 +/- 号，不配色相。
- **是否符合哲学：完全符合**（P2 + 三律）。**相容性：✅** 表格优先；ranked bars 只出现在贡献者面板。
- **明确不建议**：行内 Δ 迷你双向条（in-cell bar）列为**备选不采纳**——破坏表格对齐与扫读，等真实用户反馈再议。

### A6 · Gate 结果总览

- **帮助判断**："现在有没有 BLOCK？哪几条要我看？"——Gate 是分类事实，不是分数。
- **设计主张：Gate 总览不需要任何新图型**。五态分组清单（BLOCK 在前）+ 每态 icon+label+count 计数 pill（UI-04 已落地）就是最优解；每条规则 Result/Why/Evidence/Next 四件套。
- **一个要点**：**拒绝 "8/10 PASS" 式评分语义**——10 条规则里有 N/A、有 UNKNOWN，"分数"是伪装精确；五态计数（BLOCK·1 REVIEW·2 UNKNOWN·1 PASS·4 N/A·1）才是可复核的事实。
- **是否符合哲学：完全符合**。**相容性：✅（零新增图型）**；同时 **❌ 明确排除** gauge 指针、donut 进度环、"Release readiness 82%"——见 ②。
- **边界**：Bundle 预览是清单不是图（UI-04 右栏形态维持）。

### A7 · 跨 build 趋势（History，P1）

- **帮助判断**："最近十次 build，内存是不是一直在涨？从哪次开始涨的？"——真实需求，但也是最容易滑向 dashboard 的一类。
- **设计主张：时间序列首选"带基线的柱列（bars/columns）+ 预算线"，折线为备选**。柱列本质是 ranked bars 的时间序变体，每根可标 mono 数值；**禁重排**（时间序列一排序，趋势就死了）；**Y 轴从 0 开始**（无基线 sparkline 是点名红线）；每根柱可点回该 build 的 Analyze，框选区间直接生成 Compare。
- **是否符合哲学：符合**，前提是三条纪律：带预算线或上次值参照（不许裸线）、轴标 mono、点选可回溯。
- **相容性：⚠️ → ✅（需一次条款增补）**：折线/柱列不在现有四级优先链（链管的是"静态构成"）。建议在 DESIGN.md ⑦ 图表条款增补一行："**时间序列：保持时间顺序的 bars/columns，Y 轴含 0 基线，可叠加 budget line；禁重排、禁无基线 sparkline、禁双 Y 轴**"，随 tokens/DESIGN.md 下一次资产升版入册（建议 History 动工前完成）。
- **边界**：趋势属 History(P1)，MVP 不做；Free 档按商业模式只有单 build 分析，多 build 趋势天然是 Pro 能力，设计上不给 Free 档预留"残血趋势图"。

### A8 · 能力 banner / Evidence availability 状态栏（容易被忽略的"可视化"）

- **帮助判断**："这份分析可信到什么程度？"——ELF ✓ / MAP ○ / Git ○ 决定用户该信报告几分，是证据体系的门面。
- **价值判断：极高**；**符合哲学：完全符合**（Unknown 是一等状态的直接体现）。UI-01 已落地，此处仅声明：**它也是可视化，且优先级高于任何构成图**——证据残缺时，再漂亮的 treemap 都是误导。
- **相容性：✅** 无图型，纯状态组件。

## ② 排除清单：营销 dashboard 化陷阱（点名）

以下形态在通用 BI 世界是标配，在 FirmwareSight 全部是**红线或禁用**。每条给"为什么诱人 → 为什么错 → 正确替代"。

| # | 陷阱 | 为什么诱人 | 为什么错 | 替代 |
|---|---|---|---|---|
| T1 | **KPI 大数字卡阵列**（FLASH/RAM/Symbols/Sections 四卡横排） | 汇报时好看，"一眼看总量" | 数字脱离上下文就是装饰；DESIGN.md 明令 KPI 大数字块禁入首屏 | 摘要行：meta 字号 mono 数字 + 占比 + 环比上下文 |
| T2 | **Donut/环形占比图**（"RAM 78%"挖洞环） | 占比"直观" | 基线点名"禁滥用 donut"；环形无法排序、无法精确读数，占比信息 ranked bars 全面更优 | A1 ranked bars + 占比列 |
| T3 | **Gauge/仪表盘指针、进度环**（"Release readiness 82%"） | 领导喜欢看指针 | Gate 是分类不是分数；82% 是伪装精确 + 替用户判决，双重违规 | A6 五态分组 + 计数 pill |
| T4 | **健康分/单一风险分** | 把复杂压成一位数 | 反 Evidence-first：多维证据不可压缩为一个数字而不撒谎 | Gate 规则逐条呈现，分数永不出现在 FS |
| T5 | **彩虹分类色图表（含彩虹 treemap）** | 五颜六色显专业 | 违反单色蓝阶令；颜色参与分类编码后，色弱与黑白打印全灭 | `chart.seq.1–5` + `chart.rest`，状态永远 icon+label |
| T6 | **渐变/发光/阴影图表** | "科技感" | ② 硬性禁区点名"渐变（含图表渐变填充）"；阴影仅浮层两级 | 平色 + 1px 隔断 + 数值标注 |
| T7 | **3D 图表** | 炫 | 基线点名禁令；3D 破坏面积与角度的诚实性 | 永无替代，不进产品 |
| T8 | **数字滚动、图表生长等入场动画** | "有生命感" | 动效三档（120/150/180ms）只许面板开合/行展开/状态迁移/拖放反馈；表演性动效永不引入 | 状态迁移 productive motion |
| T9 | **伪 sparkline**（无基线、无轴、无值的小趋势条） | 塞在卡片角落很精致 | 基线点名"没有 baseline 的 sparkline"；无基线趋势可视觉放大 10% 为 300% | 真趋势 = A7 柱列；卡内不放迷你图 |
| T10 | **数据大屏 / 暗色炫酷模式** | 演示大厅需求 | FS 是工作台不是展厅；MVP 仅 Light（Dark=P1 且为可读性而非氛围） | 导出/投屏用"仪器打印件"（③） |
| T11 | **"一数据一卡"卡片瀑布** | 模块化好排 | 反模式黑名单点名；卡片+阴影+留白是营销密度，不是信息密度 | 分组表格 + 发丝线分区 |

**一个总的鉴别口诀**（评审任何新图时问一遍）：这张图拿掉颜色、拿掉动画、灰度打印之后，还剩下什么判断价值？剩下的部分才值得做。

## ③ 导出文档的视觉主张："仪器打印件"

### 3.0 定位与三个"不是"

导出报告不是分享物料，而是**可归档、可复核、脱离 FirmwareSight 仍自证的工程文件**（Release Bundle"独立可读"是既有 P0 要求，report.html 已在 Bundle 清单内）。类比是**仪器打印件 / 实验记录纸**，不是 PPT。

- 不是宣传物料：无 hero、无品牌大 logo 页、无 CTA、无结语营销句。
- 不是第二套视觉体系：与 in-app 同一个 token 真源（v0.2.0），打印只是同一系统的介质变体。
- 不是无主之档：每份报告必须能回答"谁生成的、基于哪个 artifact、能不能复现"。

### 3.1 格式分工（设计侧意见，排期以技术预研为准）

| 格式 | 定位 | 视觉主张 |
|---|---|---|
| **HTML** | 主格式（Bundle 内 report.html 延续） | 唯一承载完整视觉系统的格式；自包含（内联 CSS、无外链、离线可开） |
| **MD** | 仓库/PR/CI 友好的结构化文本 | 与 HTML 严格同构（同一数据源、两个渲染器）；图表一律退化为 markdown 表格（占比用文字列），**不画 ASCII 图**；diff 可审计 |
| **PDF** | HTML 的打印派生物，非独立管线 | HTML + print stylesheet（@media print）→ 系统打印。**不引入第二套排版真相**；分页规则：表格行不跨页断、表头重复、 specimen header 不与正文断开 |
| xlsx / docx | 数据交换场景 | 设计侧主张"结构不可丢、样式可丢"：sheet 内首行表头 + mono 无意义（Excel 自管），不追求还原视觉；docx 价值最低（脱离版本控制语境），若无明确用户信号建议不做 |

### 3.2 仪器打印件六条视觉主张

1. **版式：单栏审计文档 + 标本头（specimen header）**。A4/Letter 双兼容白底单栏；顶部不是 banner 而是"仪器铭牌"——artifact 名、SHA-256（mono、可折行复制）、Git commit/tag/dirty、toolchain、MCU 目标、时间戳、生成器版本。像检测报告的样品信息栏，一眼完成身份确认。

2. **证据分级随值而行**。每个事实字段带紧凑来源标注，四类事实口径（Observed/Derived/Declared/Unknown；组件版本场景沿用 DESIGN.md ⑥ 三词），图例在文档头一次定义：

   ```
   FLASH total   412.3 KB (Observed)   [O]
   mbedTLS       version unknown ○ (Detected from binary paths; not declared)  [U]
   ```

   标注用**文字 + 符号**，不靠颜色编码（黑白打印不丢义）。Derived 标注必须附推导来源（同 in-app "from version.h" 规则）。

3. **Unknown 的呈现：可见、可数、可行动**。报告设独立 **"Open Questions / Unknowns"** 节：中性灰 `status.unknown` + 空心 ○ + 事实句 + 每条"为什么未知 / 如何补齐"；摘要行出现 Unknown 计数（如 "2 unknowns"），**绝不淡化为脚注或折叠**；永不使用 accent 蓝。这与 in-app ⑥ 状态条款完全同构。

4. **图表：黑白可打印优先**。报告内 ranked bars / stacked bar 沿用 `chart.seq` 蓝阶，但**必须同时携带 mono 数值标注与文字占比**——灰度复印后信息不丢（WCAG 1.4.1 use of color 的打印版）；**任何图无法保证打印质量就降级为表格**。禁渐变、零阴影（打印件没有浮层，`shadow.*` 自然整体缺席）。

5. **与 in-app 一致 = 同一真源派生**。导出样式从 design-tokens v0.2.0 派生（print 媒体查询映射同一语义名）；hash/时间戳/路径/寄存器地址一律 mono + tabular-nums；状态五态 icon+label 复用；行高沿用 `table.row.compact/default`。字体走系统栈（与 MVP 拍板一致），打印件不引入 Plex 等新字体（P1 一并考虑）。

6. **可复核性是结构，不是口号**。每个结论节尾带 **Evidence 小节**（输入文件 + hash + 解析器/adapter 版本）；文末附 **Reproduction 脚注**（何输入、何版本可复现此报告——呼应确定性输出要求）；页脚 = 生成时间 + 生成器版本。全文禁用合规禁词（guaranteed / compliant / certified）。

### 3.3 报告信息结构模板（HTML/MD 同构，节序固定）

1. 标本头（build identity + 生成时间 + FirmwareSight 版本）
2. 摘要行（文字行，非卡片）：FLASH/RAM 总量 + 预算状态 + Unknown 计数 + Gate 五态计数
3. Sections 表（内嵌 ranked bars 列 + 占比 + 预算线）
4. Symbols Top-N 表
5. Diff 节（仅 compare 报告：old/new/Δ 三列 + added/removed `—` 规则照搬）
6. Gate 结果（五态分组，每条 rule / result / evidence / remediation 四件套）
7. Open Questions / Unknowns 清单
8. 证据附录（输入文件 + hash + 工具链版本 + adapter 版本）
9. Reproduction 脚注

节序即复核动线：**先验明正身 → 再看结论 → 再对证据**。任何节在数据缺失时显示"N/A + 原因"，不整节消失。

### 3.4 三个具体呈现示例（评审用基准）

- **超预算**：摘要行写 `FLASH 492.1 KB / budget 512 KB (91.9%)`，正文预算线 + 超出部分用 `chart.seq.5` 深档标注数值；**不整条染红**，是否 BLOCK 由 Gate 节说话。
- **Unknown 版本**：`mbedTLS — version unknown ○ (Detected: path fingerprint; Declare to record)`，与 in-app Declare 机制同一套词汇。
- **解析失败**：报告头部黄色 REVIEW pill + 错误四要素（What happened / Why we know / What to do / Diagnostics ID）完整随行——报告不能在证据残缺时装作完整。

## 0. 用户口径的设计转译与准入判据

用户口径：**通用不是功能多，而是让用户走得慢；便捷不是好用，而是让用户不想走。**

设计转译：

| 口径 | 设计语言 | 判据 |
|---|---|---|
| "通用 = 走得慢" | 广度不等于功能数量，等于**每次停留的判断深度**。端口的价值是让单次访问读到的证据更多、更连贯，不是让访问更频繁 | **走慢测试**：一个端口/功能若只增加"回来看的次数"，不做；若增加"每次停留能完成的判断深度"，做 |
| "便捷 = 不想走" | 留存来自**离开时带不走的工作状态**：项目记忆、时间纵深、可复现的证据链。用户留在工作台，是因为"活儿都在这台仪器上且随时可接续"，不是因为没有别处可去 | **留客测试**：粘性必须由复现力 + 状态延续 + 时间纵深构成；任何依赖迁移成本或行为回路的粘性，见 ④ 一票否决 |

**端口准入三问**（评审任何新端口先问，答不出就不做）：

1. **它打印什么证据？**——端口必须有单一主读数，且证据分级随值而行；
2. **它在什么阈值下才出声？**——打扰契约必须显式（默认静默，阈值事件才通知）；
3. **它把用户带回哪个读数？**——端口输出必须指回 in-app 的具体记录（History / Compare / Gate），不指向任何"站外落地页"。

一条总规则先行：**端口不新增第五动词**。四动词（Analyze / Compare / Gate / Release）是冻结的心智模型；任何端口都必须挂在既有动词上——输入端口服务 Analyze，CI/PR 端口服务 Gate→Release，数据端口服务 Gate/Release 的 policy 与 bundle，事件端口 watch 是 Analyze 的采集自动化、喂 Compare/History。挂不上动词的端口，默认是 Scope Creep。

## ① 新端口/集成如何不破坏"仪器"气质

### 1.0 总原则：端口是仪器上的接头，不是新开一块屏幕

仪器之所以接线越接越多而面板永不杂乱，是因为**每个接头有固定插座、单一读数、明确阈值**。示波器加了 GPIB 接口还是示波器。落到 FirmwareSight：

- **零新增一级导航**：一切集成住进既有动词视图与 Project Settings，不新开"集成中心"导航项（导航形态冻结，DESIGN.md ④）；
- **配置入 Settings，状态住在动词视图里**：端口的连接/授权属于项目级配置（与 policy 同居 Project Settings）；端口的运行状态只出现在它服务的动词视图内（如 CI 最近一次运行挂在 Release 视图侧），**不设聚合式 Integrations 面板**；
- **Overview 不吸收端口状态**：Overview 的主焦点永远是"现在能发吗"；端口状态最多以 meta 行出现。

### 1.1 防 dashboard 化

| 规则 | 内容 | 依据 / 相容性 |
|---|---|---|
| D1 不聚合 | 禁"集成健康"式聚合面板；端口状态分散住在各自动词视图 | ✅ P4 一屏一个主焦点；反模式黑名单"KPI 塞满首屏" |
| D2 一端口一主读数 | 每个端口对外呈现 = 一行状态 + 一个主读数（CI = verdict，watch = armed/last checked，编辑器 = 读数引用）；禁多卡阵列 | ✅ 《前序备忘》T1（KPI 卡阵列）的行为级延伸 |
| D3 状态不发明新语义 | 端口连通性/最近运行**复用五态词汇**（最近一次 gate run 的 verdict）或 meta 文字；"connected / syncing"类过程态用文字 + 时间戳，**不占用 status.* 色相**（第四状态色相是红线） | ✅ DESIGN.md ②⑤；tokens 无此色，私造即拒收 |
| D4 不引入新图型 | 任何端口不得以"可视化状态"为名引入新图表类型 | ✅ 图表优先级链冻结：table ＞ ranked bars ＞ compact stacked bar ＞ treemap |

鉴别口诀沿用《前序备忘》：拿掉颜色动画、灰度打印之后，还剩多少判断价值。

### 1.2 防常驻通知骚扰——通知三律

| # | 律 | 内容 |
|---|---|---|
| N1 | 阈值出声 | 出厂仅订阅 **BLOCK**（gate run 出现 BLOCK 才叫人）；REVIEW/UNKNOWN/PASS 的状态变化订阅由用户显式开启；其余一律静默写入 History |
| N2 | 一条一事 | 每条通知 = 一个可执行事实 + 证据指针（build-id / hash，mono）+ 时间戳，如 `BLOCK: gate run for build 3f2a… · 2 rules · 14:32`；禁止摘要型 digest、禁止"本周动态"打包推送（见 ④ B3） |
| N3 | 默认静默 | 所有端口出厂静默；通知是显式 opt-in 合同，设置项文案必须写明"什么情况会叫你"（what will wake you），不许含糊的"重要更新" |

- 应用内**不设通知中心、不设未读红点**——History 就是收件箱（通知只是它的阈值子集）；
- Toast 纪律延用（仅瞬时确认，不出现在错误路径，DESIGN.md ⑤）；
- **相容性**：✅ 与"错误驻留可恢复位置"一致——通知把人叫回来后，落地的是页面不是弹窗；✅ 零新图型、零新色。

### 1.3 防状态噪音

- **状态语法只有三态**：idle（meta 文字或干脆不可见）/ working（单行线性进度，明确"在做什么"，无空转转圈）/ result（状态行 + last-checked 时间戳）；
- **时间戳义务**：任何后台状态必须携带 last checked at（mono）。没有读数时间的状态行不合法——仪器读数天然带读数时刻；
- **禁动效化**：呼吸灯、脉冲、轮询动画一律不做——动效三档（120/150/180ms）只允许面板开合/行展开/状态迁移/拖放反馈，后台等待不在此列；
- **防"系统监控屏"化**：多端口并行时，各端口状态不横向铺开成网格，按所在动词视图各自一行。

### 1.4 watch 模式的克制呈现（重点方案）

心智模型：**watch 是仪器的"监测档"，不是宠物**。三档显式、全程可见：

- **Off / Armed / Triggered** 三档；Armed 必须显示采样间隔与最近检查时间（`watch armed · every 60s · last checked 14:32:05`，meta 字号、mono 时间戳）；
- **呈现位置**：不新增导航。Armed 状态条出现在它服务的动词视图顶部（Analyze/History），单行细状态，不占主焦点；
- **触发输出 = 打印件，不是弹窗**：每次 watch 触发 = History 追加一条与手动分析**完全同形态**的记录（同一证据分级、同一 specimen 字段），自动携带 vs 基准的 Δ 锚点；若用户开启通知，则为一条符合 N1/N2 的系统通知；
- **反嗡嗡约束**：采样间隔默认值与下限可见、用户可调（建议默认与下限均 60s，见 ⑥；更激进的间隔由用户自担，界面诚实标示 watch 的采集开销）；同 build-id/commit 不重复打印；短时连续触发合并通知（N2 的应用）；
- **价值定位**：watch 的真正价值 = **给时间纵深自动喂料**（替用户完成"每次 build 后跑一遍"这个动作），服务 Compare/History，不是"实时性表演"；
- **相容性**：✅ 零新图型；✅ watch 产出的序列呈现走《前序备忘》A7 时间序列三纪律（含 0 基线/禁重排/禁双 Y 轴）；✅ 与基线风险 R6（功能堆砌）相容——watch 是 Analyze 的采集自动化，不新增第五动词；⚠️ 依赖 History(P1) 排期，属 P1 形态。

### 1.5 候选端口的设计落位速判（形态归口；成本与排期以技术预研为准）

| 候选端口 | 挂靠动词 | 主读数 | 设计要点 | 红线提示 |
|---|---|---|---|---|
| 更多 artifact 格式（.axf / .su / CSV 尺寸报告 / build log 等） | Analyze | 解析后的同构 sections/symbols 表 | 能力 banner 如实标注新格式的证据等级；解析失败走错误四要素 | 禁把"支持格式数量"当营销点——支持矩阵说话（基线风险 R2） |

## ② 窄人群深度体验的 UX 主张

总论：四类 Persona——A 固件工程师（交付前确认一致性，防发错版本）、B 固件 Lead（要可复核的 diff 与证据）、C QA/合规（要结构化证据包）、D 小硬件创始人（无 DevOps 也要专业发布）——共性是**人少、多板多项目并行、发布低频高风险**。深度体验的本质是一句话：**工作台记得活儿**。其中 D 是低频用户，对 D 的粘性天然不能建立在频率上，只能建立在"每次来都接得上、走得完整"上——这决定了以下所有主张的取向。

### W1 · 项目记忆与状态延续

- **主张**：记住最近项目、上次所在视图与选中项（Analyze 行、Compare A/B 选择、Inspector 展开项、过滤词）、基准选择；重开应用回到离开时的读数。
- **价值判断：高**。嵌入式工程师多板并行，重入成本是真实痛点——A 换板子回来接得上，B 复核到一半的 diff 不丢。
- **哲学相容**：✅ 记忆内容只服务"继续证据工作"，不服务"回访频率"——不记录活跃度、不据此推送；app 级偏好与项目级 policy 分放（Settings 纪律）。
- **相容性**：✅ 零新图型；✅ P1 "Evidence 一键可达"的延伸——上次读到哪，Evidence 就在哪。

### W2 · 最近构建（Recent builds）

- **主张**：History 顶部短列表：本机分析过的最后 N 个 build，字段 = 时间戳 / build-id / verdict / Δ vs 基准。
- **三个不做**：不做"活动流"（无社交语义）；不做热度/智能排序（时间序即真相序）；不做摘要卡阵列。
- **价值判断：高**。A 的日常入口（交付前确认）、B 的复核入口（最近跑过什么、各自 verdict）。
- **哲学相容**：✅ dense not crowded（一行一 build，meta 密度）；✅ 空态给行动出口（"导入第一个 artifact"）；✅ 数字 mono + 上下文（Δ vs 基准，P2）。

### W3 · 跨 build 历史的时间纵深

- **主张**：History 不是日志列表，是**记录纸（chart recorder）**——每个 build 是一条可回放的读数；任意两条可设为 A/B 进 Compare；支持**基准 pin**（固定一个 baseline 作长期对照，是仪器概念，不是"收藏/星标"）。
- **三条纪律**（沿《前序备忘》A7）：同一单位、同一口径、可回放（每个历史点都能打开当时的原始打印件）。
- **价值判断：极高——这是对"产品单一易被替代"的直接回答**：单 build 分析可被替代；带证据链的时间纵深不可替代（数据在本机、口径由 FS 统一、每点可复现、pin 住基准即有对照系）。用得越久历史越值钱——这是**诚实的"越用越有用"**，与行为钩子有本质区别。
- **哲学相容**：✅ P2 的上下文在时间维度上就是"之前的 build"；✅ Free 档不给残血趋势（Free 边界 = 单 build 分析，多 build 纵深天然属 Pro，与商业分层一致，沿 A7 边界结论）。
- **相容性**：⚠️→✅ 呈现形态走 A7 柱列三纪律；条款增补建议见《前序备忘》⑤-1。

### W4 · 工作台常驻感

- **主张**：workbench 是台子不是页面——重开回原位（W1 联动）；当前项目名 + 当前 build 铭牌恒在标题区；未完成动作（policy 已改未存、bundle 已生成未导出）显式提示但**不催促**。
- **边界（常驻感 ≠ 常驻存在）**：不默认开机自启；不做吸睛托盘（托盘最小化可作为 OS 习惯可选项，但无红点徽标、无角标计数）；无"你 3 天没来了"。
- **价值判断：高**。"给下一步"的语调律在这里的展开是：下一步 = **证据工作的下一步**（接着复核、接着导出），不是回访的下一步。
- **哲学相容**：✅ 语调三律；✅ 未完成状态驻留可恢复位置（DESIGN.md ⑤ 错误/Toast 纪律的同族延伸）。

### W5 · 复现与交接（Persona 深耕补充项）

- **主张**：把《前序备忘》的 Reproduction 脚注与 Copy diagnostics 升格为全产品习惯：每份读数可一键拿到"何输入、何版本、何命令可复现"；C 的证据包替代截图 + Excel；D 不需要 DevOps 也走完整发布流程。
- **价值判断：高**。粘性的正当来源 = **复现力**：用户随时能向第三方（老板/客户/审核方）证明这台仪器给出过什么。
- **相容性**：✅ 全部既有机制延伸，零新增图型；✅ 与 Bundle"脱离 FS 独立可读"P0 要求同向。

## ③ 外部端口的视觉主张：打印件与联单

总隐喻延伸：《前序备忘》立了"仪器打印件"（in-app 导出）。外部端口全部是**联单**——从同一台仪器撕下来、送到现场（CI 日志、PR 评审、归档报告）的复写联。打印件留在台子上，联单送到现场去。**联单纪律四条**，三形态共用：

1. **同一真源派生**：所有外部呈现从 design-tokens v0.2.0 语义名派生（打印/文本媒体映射同一 token），不做第二套视觉体系；
2. **证据分级随值而行**：Observed / Derived / Declared / Unknown 四类事实口径随每个值标注（in-app 组件版本场景沿用 DESIGN.md ⑥ 三词 Observed/Declared/Inferred——Derived ≈ Inferred，语义同族，都必须写明来源；对照关系建议随 ⑥-2 入册）；
3. **语调三律适用于一切 bot 文案**：说事实不做判决、说未知不填空、给下一步；合规禁词（guaranteed / compliant / certified）在外部端口同样失效；
4. **可独立理解**：脱离 FS 上下文仍能读懂结论与分级——"Bundle 可独立阅读"的 P0 要求，延伸到"可独立理解"。

### 3.1 CI 输出（log / annotations）——"tty 打印件"

- **形态**：纯文本、稳定列宽、无 ANSI 色依赖（色是增强不是必需，无色环境不丢义）；证据分级用文字前缀（`[OBS]` / `[DRV]` / `[DEC]` / `[UNK]`，缩写制拍板见 ⑥）；verdict 行 = 一句话 + 五态计数（`Gate: 1 BLOCK, 2 REVIEW, 1 UNKNOWN, 4 PASS, 1 N/A`）；末行 Reproduction（命令 + 版本 + build-id）。
- **折叠纪律**：摘要 ≤ 一屏（约 24 行）；明细指向完整打印件（artifact / PR 评论），**不在 CI 日志里刷表格**。
- **禁**：emoji 表情状态（用 `[PASS]` / `[BLOCK]` 文本）、彩虹 ANSI、"🎉 Deploy successful"式庆祝。
- **相容性**：✅ 表格优先在纯文本中的同构 = 对齐列；✅ 状态 icon+label 的无图形等价物 = 文字标签 + 计数；✅ Unknown 用 `[UNK]` 前缀 + 事实句，不猜不瞒。

### 3.2 PR 评论（bot）——"评审席上的联单"

- **结构五件**：① 铭牌头（build-id / commit / toolchain / 时间戳，mono）；② verdict 一行（五态计数，不写 "unsafe"）；③ 分级计数一行（如 `4 components version unknown`）；④ Top findings ≤ 3（每条 = 事实 + 证据指针 + next step）；⑤ 折叠的完整打印件（`<details>`）。
- **语气对照**：`Gate: 1 BLOCK, 2 REVIEW` 而非 `❌ Your release is unsafe!`——判决属于 Gate 规则与人类评审，bot 只报读数。
- **排版**：单栏、无嵌套卡片、无庆祝 gif；markdown 表格 ≤ 4 列；分级用文字前缀不用色点（无障碍"不只靠颜色"与黑白打印同源逻辑）。
- **边界**：PR 评论是**通知形态的打印件**，不复制图表进 PR——图留在仪器上，联单只给读数与指回仪器的路径（准入三问第 3 问）。
- **相容性**：✅ 零新图型；✅ 语调三律；✅ 与 CI 端口共享同一数据契约（同一 IR 的两个 renderer，与技术侧"一个 IR + 多 renderer"路线同构）。

### 3.3 导出报告——"仪器打印件"的延续

- 《前序备忘》六条主张全部沿用：单栏审计文档 + specimen header；分级随值；Unknown 独立节可见可数可行动；黑白打印不丢义；同一 token 真源；Reproduction 脚注。
- 外部端口语境**新增三条**：
  - **联单编号**：页脚 = build-id + 生成时间 + FirmwareSight 版本（仪器序列号习惯——每份输出可追溯到生成它的那台"仪器"的具体状态）；
  - **分级图例随行**：报告头一次定义四类事实图例——报告必须自解释，不要求读者先学过 FS；
  - **打印派生**：PDF 由 HTML print stylesheet 派生，不引入第二套排版真相（与技术预研结论一致：不做原生 PDF 排版）。
- **相容性**：✅ 报告内图表仅用优先级链内形态；✅ 打印件零渐变零阴影（打印介质没有浮层，`shadow.*` 自然缺席）；✅ Unknown 独立节呈现，永不用 accent 蓝。

## ④ 体验粘性的设计红线（行为层反模式，点名）

**总判据一句话：仪器的可信来自它对注意力 indifferent——不渴求被使用，才值得被信赖。** 任何"想让你回来"的行为机制，都背叛 Clarity before release。《前序备忘》的 11 陷阱管**视觉层**（长什么样），本节管**行为层**（如何打扰、如何激励），互为表里；编号用 B 系列，避免与基线风险 R1–R7 撞名。

| # | 反模式 | 为什么诱人 | 为何违反品牌内核 | 替代（走慢测试的胜利） |
|---|---|---|---|---|
| B1 | **游戏化积分 / 徽章 / 等级**（分析次数积分、成就体系） | 参与度可量化、增长可汇报 | 仪器不给操作员打分——判决只属于 Gate 规则；积分把证据工作变成行为表演，Observed 事实沦为奖励货币 | W3 时间纵深：用得越久历史越值钱，这是不需要奖励的留存 |
| B2 | **streak / 连续使用天数** | 制造惯性回访 | 嵌入式工作按 build 周期不按日历；streak 的潜台词"不看 = 损失"是对用户的判决，违反语调三律"说事实不做判决" | 无替代——仪器应当随时可用、不在意你何时来 |
| B3 | **通知轰炸 / 每日每周 digest** | DAU 的标准动作 | 违反通知三律 N1/N2（阈值出声、一条一事）；alarm fatigue 在工程语境是安全级失效——真告警被淹没；digest 通常需要服务端，与 local-first / 不上云冲突 | 阈值事件通知（1.2），其余静默入 History |
| B4 | **引导成瘾 onboarding / FOMO**（功能解锁倒计时、"还有 2 个功能未体验"、空态诱导点击） | 激活率指标好看 | 能力 banner（ELF ✓ · MAP ○ · Git ○）是**事实陈述**，变成任务清单后违反 P4 与"零门槛进入"（气质约束 6）；紧迫感与稀缺感都是替用户判决 | 空态给行动出口 + 能力 banner 如实呈现；深度靠用户需要时可达，不靠提前铺路 |
| B5 | **假社交 / 排行榜 / 团队活跃度** | "团队版粘性" | 本地优先与证据私有边界——失败数据是敏感工程事实；把 Compare 的对手变成同事排行是关系灾难 | Team 层粘性 = 共享 policy 与 Bundle 互认（可复核性），不是活跃度 |
| B6 | **数据锁定式粘性**（导出格式私有化、历史不可迁移） | 最原始的护城河诱惑 | 粘性必须来自复现力而非迁移成本；Bundle 可独立阅读是 P0 承诺，锁数据 = 背叛 "Keep the evidence" | 全格式导出 + 无锁历史（W5）；离开成本 = 用户愿意放弃的记忆与纵深，不是带不走的人质 |

- **相容性总注**：B1–B6 与 Non-goals、Scope Creep 四问、语调三律、11 视觉陷阱全部同向，零冲突。与前序备忘合起来构成完整判据——**视觉层不装、行为层不缠**。

## ⑥ 留给用户/管理员拍板的四件事

1. **watch 默认契约**：默认 Off；Armed 采样间隔默认 60s、下限 60s 且可见可调；触发 = History 追加记录 + 单条系统通知（可关，出厂仅订阅 BLOCK）。我的建议：照此采纳，随 History(P1) 动工前写入 DESIGN.md。
2. **证据分级前缀缩写制**：CI/纯文本场景用 `[OBS]/[DRV]/[DEC]/[UNK]`，报告场景用全称 + 图例。我的建议：采纳（行宽友好、图例随行使"自解释"成立）；同时把"组件版本三词（Inferred）≈ Derived"的对照写进 DESIGN.md ⑥ 备注，消除两套词汇的误读空间。
3. **基准 pin 的落位**：pin 动作放 History 行内（仪器概念：固定对照点，非"收藏"），pin 后 Compare 的 A 侧默认选中该基准。我的建议：采纳。
4. **条款入册**：把"端口准入三问 + 通知三律 + B1–B6"作为 DESIGN.md ⑨ Do's & Don'ts 的行为层增补（或独立 ⑩ 外部端口条款），随下一次设计资产升版入册。我的建议：采纳——属文档级变更，不触发功能创建。

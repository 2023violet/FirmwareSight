# 背景回顾：可视化与文档导出的基线事实清单

> **任务来源**：用户提出两个 Post-MVP 探索议题——①每次分析完成后在软件内直观可视化地看到结果；②向用户提供文档导出（md/docx/excel/html 等）。本文从 v0.3.0 基线与群内已产出文件中系统提取与这两个议题相关的**全部既有事实与约束**，供后续三份探索输出（技术可行性简报、设计视角备忘等）对齐，避免重复论证或踩线。
>
> **标注规则**：每条事实标注【硬约束】= 现有治理已锁死、任何新方案不得违背（违背必须走 ADR/用户裁决）；【可扩展空间】= 基线未锁死、留有演进余地，但推进须按既定流程（ADR / 阶段门 / 依赖纪律）。

## §1 议题原文与定位

| 议题 | 内容 | 与基线的直接对应物 |
|---|---|---|
| ① 分析完成后 in-app 可视化 | "每次分析完成后在软件内直观可视化地看到结果" | MVP 已有表格 + 最小图形承诺；P1 明确列入 "richer treemap"；History P1 列入 "memory trends" |

### 2.5 明确的空白区（基线未约定，属议题②的开放空间）

【可扩展空间】基线与群内文件中**完全没有**出现 md/docx/xlsx/pdf 作为导出格式的任何约定——既无承诺，也无禁令。唯一接近的是 `release-notes.md`（作为 Bundle 输入内容而非导出格式）与 CLI JSON。结论：md/docx/xlsx 等是纯新增决策，须走依赖纪律（FS-ENG-006 七问）与（若成公共契约）版本化 schema + ADR。

## §7 对接小结：两个议题各自的"已就位 / 空白 / 红线"

### 议题① 分析完成后 in-app 可视化

- **已就位（无需重新论证）**：图表优先级与禁令、chart.seq 蓝阶、5 态与 Unknown 呈现、性能预算、SVG/Canvas 技术通道（ADR-0014）、P1 排期锚点（richer treemap / memory trends）、7 张高保真稿的基调样例。
- **空白（探索空间）**：分析"完成瞬间"的结果总览形态、treemap 下钻交互、Compare delta 可视化、Gate 结果总览、跨 build 趋势图——基线只给了优先级框架与 tokens，形态本身开放。
- **红线（不可触碰）**：no chart framework 未经 ADR 不得引入；渐变/阴影/3D/donut 零容忍；UI 不得重算 core 事实；100k 级数据必须虚拟化/分页；GPU Island 只能是 leaf adapter 且须 benchmark + ADR；营销 dashboard 化禁入。

### 议题② 文档导出（md/docx/excel/html）

- **已就位**：report crate 作为唯一生产者（ReportRenderer 端口、自包含 HTML 模板、golden 机制）；Release Bundle 品质基准（独立可读/manifest hash/preview/conflict-safe/progress/失败不留假完整）；版本化 schema 准入；确定性输出要求；措辞红线；P1 HTML share report 排期锚点；schema 目录与 reports/ 落盘位置。
- **空白（探索空间）**：md/docx/xlsx/pdf 四类格式基线零约定；导出物如何在"独立可读 + 确定性 + evidence 引用"三要求下设计信息结构；新格式在 Free/Pro/Team 中的分层归属。
- **红线（不可触碰）**：不得破坏 Bundle 7 类内容与 manifest hash 体系；不得绕过 report crate 在 desktop/ui 层自行渲染；新格式依赖必须过 FS-ENG-006 七问且 license 可商业分发；公共契约必须版本化（或明确为非契约的本地便利物）；确定性优先于美观（禁时间戳/随机 ID 破坏可复现）；导出物措辞不得越过合规边界。

# 背景回顾：已覆盖面与本轮扫描边界清单

> **任务来源**：群管理员启动第三轮 Post-MVP 探索《真需求功能全景扫描》——系统排查前两轮之外、原项目规划之外但有真实需求信号的功能。本文执行【背景回顾】：把"已经探讨过的、已经排期的、明确不做的、悬而未决的"四类边界一次性盘点清楚。
>
> **标注规则**（全文四个标注，与扫描环节接口对齐）：
> - **【已覆盖，本轮排除】**——前两轮探索已系统探讨并给出结论的主题与细分方向，本轮不再作为扫描对象；
> - **【已排期，本轮排除】**——基线 Roadmap/PRD/Lifecycle 已给出阶段归属的功能，本轮不重复"要不要做"，扫描中撞见同类信号只可用作排期佐证，不得当作"规划外新发现"；
> - **【禁区】**——基线 Non-goals/章程/lifecycle 明确不做项，扫描到的需求信号一律不立项，至多记录为"用户绕不过去的痛，需用四动词内的方案缓解"；
> - **【本轮候选】**——基线自身留下的悬置线索（被推迟项、风险暗示、无排期锚点的原文悬置、前两轮开放脑洞），是本轮扫描的重点验证对象。
>
> **一个重要澄清**：基线五份 User Stories（US-001~005）全部属于 MVP 范围，不存在"被推迟的 user story"；"悬置"主要藏在 Deferred by design 清单、风险缓解条款、SBOM/CRA 合规文档与 ROADMAP 未细化的字眼里，§4 逐条列出。

### 1.3 排除口径说明

- **主题级排除**：可视化、文档导出、端口/集成（CLI/CI/Action/watch/编辑器插件）、通用体验深化——与管理员给信息哨兵的排除清单一致；
- **结论级排除**：上两表右列——即扫描中撞见这些细分方向的信号，不得作为"新发现"上报，至多作为已有结论的外部佐证；
- **注意**：前两轮探讨的都是"方向与形态"，两轮交付稿 Q1–Q6、Q1–Q11 尚待用户拍板，**拍板结果可能微调上述结论**——若扫描发现与结论强冲突的强信号，可标注"与第一/二轮结论冲突，提请综合环节注意"，而不是直接翻案。

## §3【禁区】Non-goals 明确不做项

### 3.1 产品文档级（FS-PRD-004 Explicitly Out of Scope，8 项）

1. **不做 IDE**——不编辑 C/C++ 源码、不做 LSP、不做编译器前端；
2. **不做 Debugger**——不实现 JTAG/SWD/GDB server；
3. **不做 Flasher**——不烧录 MCU；
4. **不做 HIL**——不控制示波器/电子负载/DAQ；
5. **不做 Firmware Reverse Engineering Suite**——不做 binwalk 替代品、不做漏洞利用分析；
6. **不做 Cloud SBOM Platform**——MVP 不要求账号/云端；
7. **不做"AI 判断能否发布"**——Release Gate 必须 deterministic policy；
8. **不承诺所有 ELF 等价**——必须显示 evidence availability（这是口径纪律而非功能禁区）。

### 3.2 章程级（FS-GOV-002 非目标）

不替代 Keil/IAR/VS Code 等工具；不涉烧录调试示波器 HIL；不自动生成固件；不自动漏洞利用；不云端设备管理；不做法律合规认证；不承诺万能支持所有 toolchain。

### 3.3 MVP 推迟清单（FS-DEL-005 §8"以下全部推迟"，15 项）

Cloud、Account、Team workspace、License system、Plugin marketplace、AI assistant、CVE cloud service、Auto update、Dark theme、Custom dashboard builder、Complex graphs、Remote artifact repository、Firmware flashing、HIL、JTAG/SWD、OTA。
（注：其中部分在后续阶段有排期锚点——auto updater→v1.0、dark theme→P5、license system→B1/RC——见 §2；**本轮一律按已排期/禁区排除处理**；从未获排期锚点者见 §4.1。）

### 3.4 反模式禁跳清单（FS-DEL-005 §27"产品不要直接跳到这些东西"）

AI Chat、Cloud Dashboard、Plugin System、Firmware Flashing、Device Management、OTA、Full Vulnerability Scanner、HIL、Source Code IDE、Build System。

### 3.5 交付纪律（FS-DEL-006）

FirmwareSight 不自动扩展到：IDE、flashing、HIL、OTA、device fleet、cloud dashboard、plugin marketplace、AI judge。

### 3.6 探索层面沉淀的负面清单（前两轮）

- 技术：原生排版 PDF、PPTX/RTF/ODF、活 XLSX、PNG 光栅化、前端本地生成导出、自研二进制格式；
- 端口（D 类九条）：Plugin System、LSP/编辑器深度集成、构建系统集成、大正则通吃 parser、Flasher/OTA/设备管理、云端口、逆向/漏洞分析导入、可编程 policy DSL、AI 判断；
- 行为：B1–B6 行为红线（通知三律、禁社交化收藏、禁营销 dashboard 化等）。

### 3.7 架构红线 ADR 索引（扫描方向的相容性判据）

ADR-0004（local-first，云协作延后）、ADR-0005（可信核心无 AI）、ADR-0006（MVP 格式范围）、ADR-0013（network client deferred：签名更新/CVE feed/licensing/optional cloud 四触发条件）、ADR-0014（GPU deferred，GPU Island 仅 leaf adapter）。
**任何扫描方向若与上述 ADR 冲突，须先标注"需 ADR 级变更"再评估。**

### 3.8 易踩线方向预判（扫描高频擦边区）

- **OTA 元数据**：OTA 本身在 §3.3/§3.4 两处禁区；仅"OTA 所需元数据作为 Release Bundle 可选内容"是极窄候选，须过 Scope Creep 四问，默认不做；
- **"AI 帮你写 release notes"**：AI 判断禁入 Gate（§3.1-7）+AI Chat 禁跳（§3.4）；生成类辅助若涉 AI 须标 ADR-0005 冲突；
- **"云端团队协作"**：ADR-0004+Team workspace 推迟；Team Policy 的 Growth 排期是**本地 policy 文件共享形态**，云端平台形态属禁区。

# ADR-0033 — Object and Library Attribution from the GNU ld MAP

## Status

**PROPOSED**, implemented on `feature/m2-object-attribution` at the Owner's request of 2026-10-15 ("review, plan, then implement"). It becomes BASELINE when the Owner approves the merge after independent review. Until then, nothing here is on `main`.

## Context

`01_PRODUCT/01_PRD_MVP.md` P0-3 asks for an object or module delta "when evidence is sufficient". Since P1, `ObjectAttribution` has said *unavailable*, because no persisted record carried an object. The GNU ld MAP does carry one: every input-section row names the object or archive member it came from. `map.rs` has parsed those rows since P0 but drops wrapped rows and absolute paths, and does not skip the discarded block. Limitation L8 (`P5_KNOWN_LIMITATIONS.md`) has been carried forward ever since, waiting for "a new portable field and a feature decision". This ADR is that decision for storage and the desktop and CLI surfaces. The portable field is deferred (D7).

## Decision

**D1 — Source.** Only GNU ld MAP input-section rows after the line `Linker script and memory map`. Both one-line rows and wrapped rows (name on one line, `0xADDR 0xSIZE object` on the next) count. Special rows:
- `COMMON` rows count, attributed to their object.
- `*fill*` and `linker stubs` rows are linker-generated bytes: kept as unattributed, never assigned to an object.
- Zero-size rows are ignored.

No other toolchain is parsed (NEXT-46 rule).

**D2 — Identity without host paths.** An object reference is split into an optional archive and a member, so `path/libx.a(y.o)` gives archive `libx.a` and member `y.o`. Paths are normalized in this order:
1. Separators become `/`.
2. The longest common directory shared by all non-archive objects of the MAP is removed.
3. Any path that is still absolute (a drive letter, a leading `/`, or a UNC prefix) is reduced to its file name.
4. Archives are always reduced to their file name.

The stored key is the normalized string. No absolute path is stored, rendered or exported (AGENTS.md §7, the P1-A0 rule).

**D3 — Accounting.** A contribution is charged exactly like its output section in `MemoryFootprint` (ADR-0021):
- Flash bytes are the contribution size if the section's nonvolatile charge is known and non-zero, 0 if it is known zero, and Unknown otherwise.
- RAM follows the same rule.

Totals are never forced to reconcile. Section bytes not covered by object rows (fill, stubs, alignment) are reported as an explicit unattributed remainder per budget.

**D4 — Evidence.** Every contribution is Observed, from a MAP line whose number is kept.

**D5 — Storage.** `0007_object_contributions.sql` adds one table, keyed by build, holding ordinal, key, archive, member, input section, output section, address, size and MAP line. It is additive: no existing table, row or meaning changes. Builds stored earlier have no rows and read as "attribution unavailable: stored before ADR-0033".

**D6 — Capability.** `Capabilities.object_attribution` is `Available` when the snapshot carries at least one attributed contribution, and `Unavailable` otherwise. The reason text says why: no MAP, a MAP with no object rows, or a build stored before this ADR.

**D7 — Portable documents.** The `analysis:1` and `diff:1` schemas are unchanged. Only the existing capability values move, and the affected goldens are regenerated on purpose. Per-object rows in portable JSON need a schema version step under ADR-0022 and are a separate decision.

**D8 — Compare.** A per-object and per-library delta is offered only when both builds carry attribution. Rows are matched by key, and the Added/Removed/Changed rules are the same as for sections. A row that exists on one side is never written as 0 on the other ("Not present"). Comparability follows the weaker side. *(Implementation note, 2026-10-15: D2 keys are made unique within a build by a `#N` suffix in link order. Because that order is not an identity, a name that repeats in either build is left unpaired (Removed and Added, flagged ambiguous), the same rule as an ambiguous section name.)*

## Consequences

- L8 closes for desktop and CLI text. It stays open for portable JSON (D7).
- Snapshot ids do not change, because a snapshot id is the artifact plus MAP digest.
- The `analysis:1` documents of fixtures with a MAP change one capability value.

## Alternatives rejected

- **Re-reading the MAP at Compare time:** the file may have moved, and Compare reads stored facts only (P2).
- **Keeping full paths for disambiguation:** this breaks the no-host-path rule. The common-root strip keeps project-relative uniqueness without exposing the machine.
- **Attribution by symbol-name heuristics:** that would be Derived at best and contradicts D4.

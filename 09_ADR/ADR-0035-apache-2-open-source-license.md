# ADR-0035: FirmwareSight is open source under Apache-2.0

## Status

**BASELINE** (2026-10-18). The Owner decided it in chat on 2026-10-18: "要开源我们选择Apache-2.0". This closes known limitation L13 and the `OPEN_SOURCE_LICENSE_DECISION` item. It amends `07_COMPLIANCE/03_LICENSE_POLICY.md`, whose rule "open-sourcing needs an ADR" this ADR satisfies.

## Context

- The GitHub repository has been public, but the workspace declared `license = "Proprietary"` and had no `LICENSE` file. The code was visible without being licensed.
- ADR-0026 chose open-source, MVP-first delivery and left the licence to the Owner.
- Every third-party dependency already passes `cargo deny` against an allow list of permissive licences (0BSD, Apache-2.0, BSD-3-Clause, CC0-1.0, MIT, MIT-0, MPL-2.0, Unicode-3.0, Unlicense, Zlib). All of them are compatible with distributing FirmwareSight under Apache-2.0.

## Decision

1. **Licence.** FirmwareSight (every workspace crate, the CLI, the desktop shell and UI, scripts, schemas, fixtures generated by this project, and documentation) is licensed under the Apache License, Version 2.0. The root `LICENSE` holds the licence text verbatim, and `NOTICE` holds the project notice. `[workspace.package] license = "Apache-2.0"`.
2. **Contributions** are accepted under Apache-2.0 section 5 (inbound = outbound), as stated in `CONTRIBUTING.md`. There is no CLA.
3. **Third-party notices.** `THIRD_PARTY_LICENSES.md` is generated by `scripts/gen_third_party_licenses.py` from the locked dependency graph, with each component's own licence files. It ships with every binary release. `07_COMPLIANCE/THIRD_PARTY_VISUAL_REPORT_NOTICES.md` keeps its specific notices.
4. **Security reports** go through GitHub private vulnerability reporting (`SECURITY.md`).
5. **Unchanged:**
   - binaries stay unsigned until a signing ADR exists, which is disclosed in `SECURITY.md` and the release notes;
   - no updater, network feature or telemetry is added;
   - the `cargo deny` allow list does not grow.
6. **History is not rewritten.** Earlier validation and audit records keep what they observed then, including `Proprietary` and local paths of the development machine. They describe the past and are not edited.

## Consequences

- `deny.toml`'s `private = { ignore = true }` still excludes the workspace crates from the licence check, because they are `publish = false`. Their own licence is now Apache-2.0, not "Unlicensed".
- A release must attach `THIRD_PARTY_LICENSES.md` (or ship it in the installer) and `LICENSE`/`NOTICE`.
- 37 crates do not ship a licence file in their package. The generated list names their licence expression, and the upstream repository holds the text.

## Alternatives rejected

- **MIT:** shorter, but without Apache-2.0's explicit patent grant, which matters for a tool that embedded teams use at work.
- **A copyleft licence (GPL/MPL for the whole project):** the Owner chose Apache-2.0.

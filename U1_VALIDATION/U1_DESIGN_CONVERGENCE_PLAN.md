# U1 — Design Convergence Plan

Companion to `U1_UI_GAP_AUDIT.md` (FS-U1-001). Delivered §12 deliverable B.

## 1. Strategy

Converge in two moves, in this order, because §7.1 forbids the second without the first:

1. **Name the primitives the mockups imply and the tree does not have.** Every mockup page is built from the
   same five objects — a page header with a metadata line and an action bar, a panel with a title and a
   trailing hint, a chip, a detail column, and a state strip. None exists as a component today
   (`components/` holds four files), so each page re-declares its own version: `.page` in 6 CSS modules,
   `.header` in 5, `.mono` in 7, `.caption` in 4, `.empty` in 3. Convergence starts by writing these once.
2. **Re-order each page around what the reader decides there**, using only data the DTO already carries.
   The biggest instance is Release: `GateRunDto.counts` already holds `pass/review/block/unknown/notApplicable`
   and `findings` is documented as arriving in canonical rule order for the screen to group, yet the page
   reaches its verdict only at "3 · FirmwareSight policy readiness" (`Release.tsx:510`) after policy and
   builds.

Nothing in the plan adds a capability. Where a mockup's object needs data the product cannot produce, the
audit's §D records it and the screen does not grow it.

## 2. Component strategy

New presentational components, each in `apps/desktop/ui/src/components/` with its own CSS module:

| Component | Owns | Mockup source | Token basis |
| --- | --- | --- | --- |
| `PageHeader` | `h1` + metadata row + slot for the action bar | all seven | `--fs-font-size-page`, `--fs-font-size-metadata`, `--fs-space-*` |
| `ActionBar` | the one-primary rule of `DESIGN.md` §5, secondary and ghost siblings, right-aligned | 01–05 | `--fs-radius-control`, accent trio |
| `Panel` | surface, single hairline, `bg-surface`, title + trailing hint; **no shadow** | 01–05 | `--fs-color-bg-surface`, `--fs-border-width-hairline`, `--fs-radius-panel` |
| `Chip` | pill-surfaced label with optional state glyph; wraps `StateBadge` rather than replacing it | 01–07 | `--fs-radius-pill` (unused until now), status tokens |
| `StatusStrip` | the `✓4 ⚠2 ×1 ○1 –1` count line, from `GateCountsDto` verbatim | 04, 01 | mono + status tokens |
| `SummaryCard` | label / value / context, the second-priority card row | 01 | `--fs-font-size-metadata`, `--fs-font-size-page` |
| `RankBar` | an inline magnitude bar with its number always beside it | 02, 03 | `--fs-color-chart-blue-1..5`, `--fs-color-chart-other` (all unused until now) |
| `DetailPanel` | the right-hand column: heading, definition rows, note block, actions | 02, 03, 04, 05 | `--fs-layout-evidence-inspector-*` for width |
| `EmptyState` | the one shape "nothing here yet" takes | 06 | `bg-subtle`, hairline |
| `ScrollArea` | the `.viewport` wrapper that owns `overflow-x`, replacing `display: block` on tables | F2R-01's own rule | spacing tokens |

Rules that bind all of them:

- Every length, colour, radius, duration and font size is a `var(--fs-*)`. **No new token value exists in
  this round**: `assets/design-tokens.json` is frozen under ADR-0018 and `styles/tokens.css` is generated by
  `scripts/generate_design_tokens.py`. If a mockup effect needs a number the file lacks, the effect is not
  built and the case is recorded.
- No `box-shadow` (the tree has zero today and `DESIGN.md` §9 forbids it on cards, panels and table rows).
  Depth comes from `bg-canvas` → `bg-surface` → hairline → alignment.
- Status is always icon + label; `RankBar` always carries its number, so colour is never the carrier.
- UNKNOWN keeps its hollow glyph and neutral grey and never borrows accent blue.
- Keyboard order equals visual order; the focus ring stays `--fs-focus-ring-*`.
- Components stay presentational: no page imports a parser, diff or gate computation into one
  (`AGENTS.md` 3, `DESIGN.md` §9).

## 3. Page order and per-page intent

Following §4's priority, with the audit's §E reasoning:

1. **Shell + shared layer** (prerequisites for everything below).
2. **Overview** — new page, `FS-UI-01`. Composition only: `AnalysisSummaryDto` (capabilities → the ELF / MAP /
   Git cards; `MemorySummaryDto` budgets → flash card; `sectionCount`/`symbolCount`), `GateRunDto`
   (`counts`, both severity aggregates, `createdAt`, `runId`) → the readiness band, and
   `list_history_gate_runs` for "latest stored evidence". Every card states its evidence and its next step;
   with nothing analyzed in the session the page says so and points at Analyze rather than showing zeroes.
3. **Analyze** — `FS-UI-02` + `FS-UI-06`. Chip row from `CapabilitiesDto`; sections and symbols as panels with
   `RankBar`; the existing Inspector becomes the `DetailPanel`; `DetailError` is retired in favour of
   `ErrorPanel`; the parse-failure card gains the mockup's "nothing was overwritten — the workspace still
   holds the last good artifact" line, which is a true statement about `lastGood` in `App.tsx:90-92`.
4. **Release Gate** — `FS-UI-04`. `div.page` → `main.page`; verdict band first with `StatusStrip`; findings
   grouped BLOCK → REVIEW → UNKNOWN → PASS → N/A in the order `03_DESIGN/06_UI_REFERENCE_SCREENS.md` fixes;
   bundle preview as the paired `DetailPanel`; the six numbered sections keep their content and lose their
   monopoly on order.
5. **Compare** — `FS-UI-03`. Summary band with the gate chips beside it; the existing ranking becomes the
   right-hand contributors panel; `ScrollArea` replaces `display: block` on the change tables
   (`Compare.module.css:411-417`).
6. **Bundle & History** — `FS-UI-05`. Header metadata + action bar; a selected row drives a right-hand
   detail card built from the row's own DTO fields; the three registers stay three registers, because they
   are three different id spaces and the mockup's single merged list would be a claim the data cannot keep.

## 4. The one non-CSS change, declared here rather than discovered later

Overview needs a window title, and titles are composed in Rust from a closed set so a file name can never
reach a window property (`App.tsx:9-13` records why). That set is `MainWindowPage`
(`apps/desktop/src-tauri/src/ipc.rs:1260-1266`) with its `window_title` match and the five-variant list in
`tests/history_reads.rs:571-575`. Adding `Overview` means: one enum variant, one match arm, one regenerated
ts-rs type, one test list. No command, no DTO field, no storage, no wire or golden change.

This is the only place the round reaches outside `apps/desktop/ui/src`, and it is the delivered §5's
"prove it is the minimum necessary and say so in the report" clause being used exactly once. The rejected
alternative was to title the Overview window "Analyze", which would make the title bar lie.

## 5. Risk list, stated before the work

| Risk | Mitigation |
| --- | --- |
| UI test count moves (225 → higher). Every P5 round treated a moving count on a *docs-only* round as a STOP; this round is not docs-only, so the count must move and must be reported exactly | New structure contracts are added deliberately, and the report states the delta with per-file counts, never "tests added" |
| Regressing the F2R-01/02 layout contracts (`details.test.tsx:767-786`, `:751-764`, `history.test.tsx:527-543`, `:545-557`) | Those tests pin `.viewport` + native `display: table` and the leading row action. The new `ScrollArea` keeps both, and the existing tests run unchanged in the same commit |
| Overflow at the frozen 1024×720 minimum when a two-column page gets a detail panel | Detail panels use the existing `--fs-layout-evidence-inspector-min` (320 px) as the column floor and stack below the content column when the page cannot hold both; measured at 1024×720 and 1440×900 |
| Overview reading as a second source of truth for the gate verdict | It displays `GateRunDto` fields verbatim and links to Release for every decision; no severity is computed in the UI |
| ts-rs generated drift failing `drift/generated dtos` in the gate | Regenerate as part of the same commit and run the full 17-step gate locally before pushing |
| Accessibility regression from new interactive structure | `aria-current`, `aria-sort`, live regions and focus order are preserved per page; each new component states its role in its first test |
| Scope creep toward the mockups' unfounded features | The audit's §D table is the boundary; anything not in §C's backing list is not built |

## 6. Validation plan

- **Automated, in-repo:** `cargo fmt --check`, `clippy -D warnings`, `cargo test --workspace`,
  `pnpm typecheck`, `pnpm lint`, `pnpm test`, and `python scripts/check.py` (17 steps) — with the Rust and UI
  totals read from section-scoped log lines, not from a whole-gate sum.
- **Structural contracts in vitest:** one per new component (role, token class, no colour-only state), and
  per page the ordering claims this plan makes (verdict band precedes the rule list; the detail panel is a
  sibling of the table, not a child; every table that scrolls does so in a wrapper).
- **Visual before/after:** requires the real desktop window, which means a build plus a parked owner store.
  That is a machine-level operation, so it is requested separately rather than assumed. If it is not
  authorized, the report records `VISUAL_CONVERGENCE = STRUCTURAL_CONTRACTS_ONLY` and says which claims are
  DOM-asserted rather than screenshot-proven — it does not describe pixels it never saw.

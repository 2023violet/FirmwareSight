### 5.1 Defect E, in full

`.gitignore` line 2 is `**/target/`, written for Cargo build directories. It matches any directory of
that name, and P2's fixture pair names its new side after the diff vocabulary — `fixtures/elf/p2-diff/target/`
(prompt §28 uses exactly that path). So `firmware.elf`, `firmware.map`, `firmware.ld`, `fixture.toml`
and both source files in that directory never entered the repository, while `fixtures/manifest.json`
recorded all twelve P2 paths from the commit that introduced the pair, `c7fc2a3`.

Nothing in the local gate could see it, because every step reads the working tree and the files *were*
in the working tree — the generator had written them there. `p0_acceptance.rs` hashes whatever it finds
at a manifest path, so it passed; `p2_fixture_pair.rs` passed; both P2 goldens matched; the CLI smoke
and the desktop smoke both analyzed real bytes. Eight further commits were built on a repository that
did not contain the fixture it claimed.

The remote had no such indulgence. Two P2 commits were pushed during the round, and the run that push
started failed:

```
run 36596452341 (#17)  on c7fc2a3  event push  completed / failure
  Rust (windows-latest)   failure    Rust (ubuntu-latest)  failure    macOS Core Smoke  failure
  Desktop UI (both)       success    Generated output drift success   Dependency policy   success

test committed_fixtures_match_their_recorded_hashes ... FAILED
thread '…' panicked at crates/firmwaresight-artifact/tests/p0_acceptance.rs:66:35
```

Line 66 is the `unwrap_or_else(|err| panic!("cannot load {relative}: {err}"))` on a manifest path, which
on a clean checkout is the missing target half.

Fixed in three parts, committed as `cfee1e5`:

1. the six target fixture files are tracked;
2. `.gitignore` un-ignores `fixtures/elf/p2-diff/target/` and says why in the comment above the rule, so
   the next person meets an explanation rather than a surprise;
3. the drift group gained `fixtures tracked`, which compares every path `fixtures/manifest.json` records
   against `git ls-files`. It is the only step in the gate that inspects the index, and it is the guard
   against this class: a green run over a repository that does not carry what it says it carries. Its
   detection was tested by pointing it at a scratch repository whose manifest names a file the index
   does not have — it reports `fixtures/missing.txt is recorded in fixtures/manifest.json but is not
   tracked by git` and fails the step.

Re-verified from a clean tree, not from the authoring directory:

```
git archive HEAD | tar -x -C <temp>          # 22 manifest entries, 0 missing, 0 hash mismatch
cargo test -p firmwaresight-artifact --test p0_acceptance    → 19 passed; 0 failed
cargo test -p firmwaresight-artifact --test p2_fixture_pair  → 12 passed; 0 failed
python scripts/check.py --only drift          → 6/6 PASS, including drift/fixtures tracked
```

## 6. Not verified

- **Desktop smoke step 27** (inducing an invalid compare attempt in the shipped window) is `PARTIAL`,
  because the native `<select>` popup cannot be driven or captured through the available window path.
  The behaviour is covered by `compare.test.tsx` and the IPC tests and was **not** observed in the
  running app. Details in the smoke report.
- **The rebuilt desktop binary was not re-smoked.** `cargo build --release --features custom-protocol`
  over the final tree produced `firmwaresight-desktop.exe` sha256
  `11401b8a9c2df08c5a291402a6bddde4dac0107478f1df77df28f8bc7e846817`, which differs from the
  smoke-tested `f6f9db40…` because of defect D. D cannot reach the desktop path — the desktop reads
  `layout_source` back out of the database, which is why its export in the smoke was already correct
  — so the rebuild was verified by the Rust gates and by §4.5, not by a new window session.
- **The final tree has no remote run.** `origin/main` is still at `c7fc2a3`, whose run is red, and the
  commits since it — including the fix — were never pushed. So this round closes with `LOCAL PASS` and
  a red remote branch: the red belongs to an intermediate commit and is already fixed at HEAD, but only
  a push turns that into a green run. Pushing is a shared-state action and is left to the owner's
  decision rather than taken here.
- **What the red CI proves about the gate.** Before defect E, a locally green `check.py` did not mean a
  clonable repository. That gap is now covered for fixtures only. The same class still applies to any
  tracked-expected file that is not in a manifest — for instance a source file ignored by accident,
  which no step checks.

# What this unit is for

Stages 1 and 2 proved the library and the portable document. Neither put a control in front of a person: at
`3cfbc03` there is still no UI section, no `--attach`, no IPC command, and `BIN_HEX_RELEASE_ATTACH` is
`DESIGN_APPROVED / NOT_USER_AVAILABLE`. U4 turns tested library behaviour into a workflow one user can operate
through the desktop app and the CLI, and then proves it in an **installed** build, not a dev server.

Entry condition, measured rather than assumed: stage 1's and stage 2's local objective checkpoints are both green
(`920e764`, then `3cfbc03`; 17 of 17 at each, 960 then 987 Rust), the tree is clean, `main` is 4 commits ahead of
`origin/main` with no divergence, and the ancestry is the packet's own.

# Preflight, measured (each of these was read, not presumed)

1. **The CLI is `clap` derive, not hand-written parsing** — `clap = { version = "4.6.7", features = ["derive"] }`
   at `apps/cli/Cargo.toml:19`, `use clap::{Parser, Subcommand}` at `main.rs:24`. `GateArgs` is `main.rs:174-199`
   and `ReleasePrepareArgs` is `main.rs:90-123`. A repeatable flag is therefore `Vec<PathBuf>` with
   `#[arg(long, value_name = "FILE")]`, and clap's own error type already maps to the frozen usage code 2
   (`main.rs:762-786`).
2. **The library already refuses `elf`/`map` as attachment kinds** — `observe_attachment` starts with
   `if matches!(declared_kind, ArtifactKind::Elf | ArtifactKind::Map)` → `KindNotAttaching`
   (`crates/firmwaresight-project/src/evidence.rs:417-425`). So prompt §10's "never allow Elf/Map to satisfy an
   attachment" is a property of the existing entry point, and U4 must not weaken it.
3. **The attachable vocabulary is exactly three kinds** — `ArtifactKind::{Bin, IntelHex, Unknown}` with words
   `bin` / `hex` / `unknown` (`crates/firmwaresight-core/src/domain/identity.rs:115-135`), and `from_word`
   deliberately does not read `unknown` back (it is attachable but names no requirement). Test helpers already
   encode this triple (`release_attachments.rs:990`).
4. **§9's Gate-wording rows are already landed** — `artifacts.required` answers in three branches including
   "…from release attachments (bytes verified, provenance not verified)" (`core/domain/gate.rs:1123-1143`), the
   missing case distinguishes the two sets (`:1145-1164`), and `artifacts.hashes` counts both classes
   (`:1201-1206`). U4 does not touch them. What §9 still owes and U4 owns: the Analyze refusal clause
   (`firmwaresight-artifact/src/error.rs:87`), the Release caption (`Release.tsx:839-841`), the new section, the
   bundle preview rows, the report limits line, the CLI flag, the storage invariant sentence
   (`firmwaresight-storage/src/gate.rs:267-268`, still "a changed policy, workspace or baseline"), and the Help /
   Getting Started pointer.
5. **The desktop persists an empty attachment set on purpose** — `release.rs:255-264` calls
   `persist_gate_run` with `attachments: &[]` under a comment that says nothing attaches a file yet. That comment
   is this unit's deletion.
6. **Session state is token-keyed and paths never cross** — `SelectionStore` (`lib.rs:88-111`), `BundleStore` /
   `HeldBundle` (`:196-229`), `DestinationStore` (`:241-257`), all held on `Session` (`:262-277`). An attachment
   store follows the same shape: a token the UI holds, a `PathBuf` Rust keeps, a leaf name the UI may show.
7. **The native single-file picker already exists and is already used** — `intake::pick_path`
   (`apps/desktop/src-tauri/src/intake.rs:31-37`) wraps `app.dialog().file().set_title(…).blocking_pick_file()`,
   used for the artifact and the MAP (`:85`, `:104`). `tauri-plugin-dialog` is already a pinned dependency and the
   capability set stays as granted, because the dialog opens from Rust. **No new native capability, no plugin, no
   lockfile change is needed** — which is the difference between proceeding and the prompt's STOP.

# The one preflight finding that changes the design

**The P4 golden byte-compares the release report HTML.** `GOLDEN_FILES` includes `REPORT_DOC_NAME`
(`apps/cli/tests/p4_golden.rs:33-39`) and `the_golden_documents_are_the_bytes_the_shipped_binary_wrote` compares
generated bytes against the committed file (`:339-350`). §9 tells the `release-report.html` limits table to gain a
line about attachments, while U4's own prohibitions list says no changes to the P4 golden. Both hold only if the
line is **conditional**: a bundle that ships no attachment renders exactly the bytes it renders today, and a
bundle that ships one gains the sentence. The compatibility test for that is the golden itself — if an
unconditional change were made, `drift/goldens unchanged` and the CLI golden test would both fail, and this unit
would have to STOP rather than regenerate a golden.

# Design

**Declared kind rule (library, shared by both edges).** A new `declared_kind_for_path(path) -> ArtifactKind` in
`firmwaresight-project`, next to `AttachmentSelection`: `.bin` → `Bin`, `.hex` → `IntelHex`, anything else →
`Unknown`, compared case-insensitively on the extension only. It never opens the file, never looks for a record
structure, and can never return `Elf` or `Map`. The CLI has exactly one carrier (`--attach <FILE>`) as §9 freezes,
so this name rule *is* its declaration rule, and it is documented as a name suggestion the person invoked by
typing the flag — not a content claim. The desktop offers the three kinds explicitly and defaults the picker to
this suggestion.

**Desktop IPC.** Four new use-case commands, all registered in `lib.rs`'s handler list:
`attach_release_file` (native pick → observe → store → return the row), `set_release_attachment_kind` (token +
kind word from the closed three), `remove_release_attachment` (token), `get_release_attachments` (the current set).
`run_release_gate` threads the set into `build_context_with_attachments` and into
`GateRunDraft { attachments }`; `prepare_release_bundle` / `export_release_bundle` move from `prepare` / `publish`
to `prepare_with_attachments` / `publish_with_attachments`. DTOs are ts-rs types exported to
`apps/desktop/ui/src/ipc/generated/`, so `drift/ipc bindings unchanged` keeps its meaning and the UI renders values
it did not compute. No path, no directory, no host absolute path crosses.

**Staleness.** Rust owns the invariant — the run id already binds the set, the store refuses a rewrite, and the
bundle refuses a set that changed after the preview (`ERR-BUNDLE-6118`). The UI's part is a presentation decision
about its own control: pressing Attach/Remove clears the displayed run and the held preview, the same way the
screen already drops a plan when the owner moves to another run, and shows the last-successful-run sentence in the
existing `styles['stale']` shape. The UI decides no verdict and computes no digest.

**Copy.** Verbatim from §9: the section is "Release attachments", the verbs are **Attach** and **Ship** and never
Analyze, and the limitation sentence is "Bytes verified; build provenance not verified. BIN/HEX contents are not
analyzed." The Analyze refusal keeps its sentence and gains the following clause that points at Release. Nothing
here says address span, record checksum, symbols, memory, or "valid Intel HEX".

# Test list, before implementation

- Library: the name rule (`.bin`, `.BIN`, `.hex`, `.Hex`, `.ihex`, no extension, a directory-shaped name), and that
  it never yields `Elf`/`Map`; the existing `KindNotAttaching` refusal still fires when a caller asks anyway.
- CLI integration (`CARGO_BIN_EXE_fwsight`, real process, exit codes, stdout/stderr split as the existing
  `gate_cli.rs` / `release_cli.rs` do): one `--attach` BIN + one HEX satisfies `required = ["elf","bin","hex"]`;
  a missing required kind BLOCKs; the same invocation with no `--attach` is byte-identical to today's documents;
  a nonexistent path, a zero-byte file and a directory each answer with the typed refusal and the frozen exit code;
  bytes changed between `prepare` and `publish` refuse and leave no partial bundle; mixed-case names keep their
  declared kind.
- Desktop backend (`bundle_ipc.rs` style, a session over a temp database, no window): the pick → observe →
  durable run → preview → export → independent-verify chain; the token never leaks a path; a set change after a
  run makes the stored run's set and the current set disagree in the DTO and the export refuses.
- UI (`release.test.tsx`, mocked bridge, asserting only what the shell sent): the section lists leaf, size, full
  SHA-256, kind and the limitation sentence; UNKNOWN renders neutral, not an invented PASS; Attach/Remove keep
  keyboard focus and do not strand the reader; a stale run cannot still show a ship-ready label.
- Installed: real Windows package, disposable profile, real picker, real export, re-hash of the shipped bytes.

# Stop conditions carried from the packet

No lockfile, migration, schema-major, capability or native-plugin change; no new `ERR-BUNDLE-61xx` code; no edit
to the `/1` canonical text, the P4 goldens, the V1 cohort, the publishing channel or the design tokens; no BIN/HEX
parsing; no claim of installed evidence that a screenshot from a dev server stands in for; no
`PASS_COMPLETE` / `USER_AVAILABLE` / `SUPPORTED_WITH_LIMITS` without independent acceptance, and the
compatibility matrix moves only where this round actually measures a run. `C1-U4`'s local word is
`LOCAL_USER_WORKFLOW_GATE_PASS / ARCHITECT_REVIEW_PENDING`; `READY_FOR_ARCHITECT_PRODUCT_ACCEPTANCE` is added only
if the packaged runtime evidence exists. **No push** — separate owner approval, normal fast-forward only, never
force.

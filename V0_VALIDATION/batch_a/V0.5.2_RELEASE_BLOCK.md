# v0.5.2 Release Block

`FirmwareSight_Project_Baseline_v0.5.2` is intentionally not generated.

Reason:

The authorized Batch A Prompt permits v0.5.2 only after:
- 4–5 real eligible external participants complete Batch A;
- their real Session evidence is written into the project.

Current:
- real eligible external participants: 0
- formal Session evidence: 0

Creating v0.5.2 now would violate the V0 evidence-integrity rule and would imply a Batch A Evidence Patch without evidence.

Release block clears when PA-001…PA-004/005 real evidence exists and Batch A Interim Review is completed.

## Historical note, added 2026-09-29

This file is left as written, including its name and its `v0.5.2` subject, because it is the record of a
decision taken under the pre-P0 baseline. Three things have moved since, and they belong here so the note
is not read as a live plan:

- `FirmwareSight_Project_Baseline_v0.5.2` was the **pre-P0** planned Batch A evidence-patch version. The
  live project baseline is `v0.6.0`, promoted later by the P0 Final Promotion.
- `v0.5.2` is therefore **not generated**, is not generated when Batch A completes, and no older baseline
  is created after `v0.6.0`. The project version is never decremented to fit a research document.
- Completing Batch A does **not** automatically create any project baseline version. Version promotion
  after Batch A and the interim review is an architect decision, recorded through the normal promotion
  path, not a consequence of reaching `4-5` sessions.

The block's original condition still holds in the part that matters: no evidence patch without evidence.
As of this note the count is unchanged - `0` real eligible external sessions, `0` formal session records.

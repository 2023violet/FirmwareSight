# Moderator Guide

## Opening script

> This is a local desktop-tool prototype for analyzing, comparing, checking and recording evidence before a firmware release.
>
> Please use it as if you were seeing a new tool for the first time. Think aloud while you work.

Do not explain:
- Observed/Derived/Declared/Unknown;
- Gate states;
- Compare navigation;
- Bundle purpose;
- MAP requirement.

## Session order

1. consent/privacy;
2. background questions;
3. Tasks 1–10;
4. discovery/interview questions;
5. price/pilot questions;
6. debrief.

## Moderator discipline

- Do not rescue early.
- Record exact hesitation before intervention.
- Mark every intervention.
- Do not praise a “correct” answer.
- Do not call a product behavior “obvious”.
- Do not tell the participant what FirmwareSight is “supposed” to mean.

## Critical wording watch

If “Can we ship now?” is interpreted as legal/compliance/safety approval, record M13 Critical.

## State preparation

Before each session:
- reset prototype to STATE A;
- confirm MAP absent;
- confirm mbedTLS Unknown;
- confirm OTA review pending;
- confirm signature BLOCK;
- confirm no current bundle has been created.

# P1-A0 Design Review Checklist

`AGENTS.md` 11 requires every UI change to pass `templates/DESIGN_CHECKLIST_TEMPLATE.md`. This is
that checklist filled for the P1-A0 screen, which replaced the P0 fixture selector with artifact
intake. Authority order where sources disagree: governance red line > frozen assets, ADR and tokens >
`DESIGN.md` > accepted screenshots > upstream reference.

Read before writing: root `DESIGN.md`, `assets/design-tokens.json` (v0.2.1),
`apps/desktop/ui/src/styles/tokens.css` (generated), and the P0 pass in
`P0_TECHNICAL_VALIDATION/P0_DESIGN_CHECKLIST.md`.

**No new design token was required, so prompt §21's STOP condition was not reached.** The only token
this slice consumed is `border.width.hairline`, which the Design Contract Closure Addendum
authorized and `ecd1c87` committed before this work began; `tokens.css` was regenerated by
`python scripts/generate_design_tokens.py` and never hand-edited (`drift/design tokens` → PASS).

Method: each ⚙ box was checked against the tree with the command written inline, so the review can be
repeated. Unticked boxes carry the reason beside them.

## Don'ts（禁区 · 一票否决）

- [x] ⚙ **No gradient.** `grep -rniE "gradient" apps/desktop/ui/src --include="*.css"` → no match in
      any authored sheet or in the generated `tokens.css`.
- [x] ⚙ **No glassmorphism.** `grep -rn "backdrop-filter" …` → no match.
- [x] ⚙ **No neon or glow.** `grep -rniE "box-shadow|text-shadow|drop-shadow" …` → no match. The new
      `.stale` note and the unchanged `.error` panel both build hierarchy from a hairline plus
      `bg.subtle`, exactly the `DESIGN.md` 4 device ("靠对齐、分组、发丝边框和排版建立层级").
- [x] ⚙ **No purple-blue palette, no hardcoded colour.** The same grep for `#[0-9a-fA-F]{6}` returns
      one hit and it is prose: a comment in `App.module.css:101` naming `#98A2B3` while explaining the
      disabled-label defect. Every rendered colour arrives as a `--fs-color-*` variable.
- [x] ⚙ **No shadow beyond the overlay pair.** Nothing is authored, so nothing can exceed.
- [x] **No marketing surface.** The header is a title plus a two-line subhead that states a limit.
      The new control row is a button, a file name and a MAP state - no hero, no CTA, no illustration.
- [x] **State is never colour-only.** Every state still goes through `StateBadge` (icon + label +
      optional count + note). The two new text-only states deliberately carry no colour claim at all:
      `MAP: Not provided` and the `.stale` note are secondary text. The in-flight region is announced
      by `role="status"`, not by a spinner's colour.
- [x] **No dark theme.** No `prefers-color-scheme`, no `.dark` rule, no theme attribute.
- [x] ⚙ **No invented values.** The complete set of literals with units in the three authored sheets
      is `60ch` (the subhead measure), `100%` (the html/body height reset) and `0ms` × 2 (the
      reduced-motion reset) - all three pre-existing and none of them a colour, spacing, radius or
      motion value. Zero `px` literals remain in `App.module.css`: the P0 sheet's eight structural
      `1px solid` borders are now `var(--fs-border-width-hairline) solid`, used 9 times in this file.
      112 references across 41 distinct tokens, counted over the three authored sheets
      (`App.module.css`, `components/StateBadge.module.css`, `styles/global.css`); the generated
      `styles/tokens.css` is excluded from that count.
- [x] **UI does not re-implement parser / diff / gate logic.** The screen renders the DTO; the new
      `source` field is a label the Rust side chose, and no capability word is re-derived in TS -
      `capabilityState()` maps a returned word to one of the five frozen states and nothing more.
- [x] **Banned phrasing absent.** No "guaranteed", "fully compliant", "zero risk", "intelligent
      detection". The copy says what the build is not: "No diff, no gate, no release action exists in
      this build."

## Do's（应做 · 逐项勾选）

### 状态与证据

- [x] ⚙ **Five states, correctly presented.** `StateBadge` unchanged in contract; the new MAP row
      uses `N/A` (dash icon + `not-provided`), not `UNKNOWN`, because the user chose not to supply an
      optional input. Asserted by `reports a missing MAP as an absent optional input, not a failure`.
- [x] ⚙ **Interaction states complete.** `.primary` has hover / active / focus-visible / disabled;
      the three secondary buttons share it. `.selected` and `.meta` are static text, marked N/A for
      hover rather than given a decorative one.
- [x] ⚙ **Focus ring 2px + 2px offset, never weakened.** `styles/global.css:51-54` still reads
      `outline: var(--fs-focus-ring-width) solid var(--fs-focus-ring-color)` with
      `outline-offset: var(--fs-focus-ring-offset)`; no rule in the diff removes or overrides it.
- [x] **Unknown stays neutral.** `Git` renders `unknown` with a hollow icon and no accent; the new
      code never routes a missing input through `UNKNOWN`.
- [x] **Error carries its four-plus-one parts.** What happened / Code / Why we know / What to do /
      Diagnostics ID, in the unchanged `ErrorPanel`, and the panel now sits *above* the surviving
      last-good report instead of replacing it.
- [x] **Dialog only for real interruption.** The native file picker is the only dialog in this build
      and it is the feature. No alert() and no confirmation toast exists.
- [x] **Empty state has an exit.** `Nothing has been analyzed in this session yet. Choose an artifact
      and run Analyze.` - a named region (`No analysis yet`) with the next action in the sentence.
- [x] **Next step always visible.** The strengthened/weakened evidence note says what would change it
      ("Supply the linker MAP to strengthen it"), and the failure note says which file the surviving
      report belongs to.

### 数字与密度

- [x] ⚙ **mono for numbers, hashes, versions, ids.** The new `File` row is mono only when the value is
      a hash-like token; `selectionId` is never rendered, so there is no new id surface. The
      `.stale` note is prose and stays in the text font.
- [x] ⚙ **Row height within budget.** Rows still use `--fs-row-default` with `--fs-space-2` padding;
      no rule in the diff raises a row above the 40px ceiling.
- [x] ⚙ **Spacing on the 4px grid, radii in the frozen set.** Every new declaration uses
      `--fs-space-*` and `--fs-radius-control` / `--fs-radius-panel`.
- [x] ⚙ **Font size ≥ 12px.** No new font size was authored; the new `.meta` reuses
      `--fs-font-size-metadata`.
- [x] ⚙ **Motion within the frozen durations.** The only transition remains
      `background var(--fs-motion-duration-micro) var(--fs-motion-ease)` on `.primary`.
- [x] ⚙ **`prefers-reduced-motion` respected.** `styles/global.css:63-70` untouched.
- [ ] **Diff row three columns.** N/A: no diff exists in this build, and adding one is §24 non-scope.
- [x] **Key numbers keep their context.** The budget figures sit beside a state word and a basis
      sentence; the MAP row states which file is attached rather than implying a stronger claim.
- [x] **One primary focus per screen.** Exactly one `.primary` button (Analyze); the pickers are
      secondary, and Analyze is disabled until a selection exists so it cannot be the loudest thing
      on a screen that cannot yet act.
- [x] **Review amber deepening.** N/A in this diff: no `REVIEW` state was newly authored, and
      `StateBadge` already handles the small-text variant.

### 图表与可访问性

- [x] **Chart priority / anti-patterns.** N/A: this build renders no chart.
- [x] ⚙ **Icon buttons have accessible names; semantics are real.** All controls are `button`
      elements with text names, the report sections are `section[aria-label]`, and the status and
      error regions use `role="status"` / `role="alert"`.
- [x] ⚙ **Tab order = visual order.** The controls are in DOM order (choose → MAP → analyze) and
      nothing is tab-reordered; the native dialog owns focus while it is open.
- [x] **Capability banner reflects evidence honestly.** `MAP: Not provided` matches
      `capabilities.map = not-provided`, and the strengthened pass was verified in the real window
      against `fwsight analyze --json` for the same bytes.

## Findings from this pass

1. **Fixed here: disabled labels faded out.** `text.disabled` and `accent.disabled` are both
   `#98A2B3`, so P0's `.primary:disabled` painted the label in its own background, and the new
   `.control:disabled` paired the same token with `bg.subtle` (`#F1F3F5`) - about 2.3:1, below even
   the 3:1 floor for a control's text. Both rules now use `text.secondary` on `bg.subtle` (≈5.2:1)
   with a `border-default` outline: tokens only, no new value, no new token. The re-shipped binary was
   re-checked in the window. The P0 checklist's finding on the same pairing is left as it was written;
   history is not rewritten to make this look planned.
2. **The hairline gap is closed, not re-opened.** P0 recorded `border.width` as a contract gap. The
   addendum resolved it in tokens v0.2.1 with exactly one semantic (`border.width.hairline = 1`), and
   this slice is the first UI work that consumes it: 9 uses in `App.module.css`, 0 remaining `1px`
   literals.
3. **Open, not a styling decision.** `.stale` and `.error` are both hairline + `bg.subtle` boxes, which
   is deliberate (an error is not a different visual species), but it means the two are told apart by
   the left accent border and the heading alone. Whether the last-good note deserves its own semantic
   role is a design-contract question for the next design round, not something to invent here.
